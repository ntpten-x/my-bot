# แก้สวิตช์และการลบชุดคอมเมนต์

## สรุป

ชุดที่ยังไม่ผูกบัญชีถูกล็อกสวิตช์ ส่วนบางครั้งสวิตช์ที่บันทึกสำเร็จกลับแสดงค่าเก่า และยังไม่มีปุ่ม/API ลบชุด แก้โดยแยกสถานะที่เจ้าของเลือกออกจากความพร้อมส่ง ใช้ลำดับคำขอป้องกันผลโหลดเก่าทับข้อมูล และเพิ่มการลบออกจากรายการแบบเก็บประวัติ

การแก้อยู่ใน working tree ของ `master` ยังไม่ได้สร้าง commit/PR จุดอ้างอิงหลักคือ `src/app/(app)/auto-comment/page.tsx`, `src/lib/auto-comment/admin.ts`, `src/lib/auto-comment/rule-archive.ts` และ `src/app/api/auto-comment/rules/[id]/route.ts`

## อาการและสาเหตุ

1. หน้าใช้ `disabled={Boolean(toggling) || (!rule.enabled && unbound)}` ทำให้กดเปิดชุดที่ยังไม่ผูกบัญชีไม่ได้ ฝั่ง `setCommentRuleEnabled` ยังนำข้อกำหนดบัญชีออนไลน์มาใช้กับการเก็บสถานะ แทนที่จะตรวจในเส้นทางส่ง ผู้ใช้จึงตั้งเปิดไว้รอความพร้อมไม่ได้
2. `reload` ใช้ boolean `reloading.current` และ return ทันทีเมื่อมี GET ค้างอยู่ หากกดสวิตช์ขณะ GET เก่าค้าง การ reload หลัง PATCH ถูกข้าม เมื่อ GET เก่ากลับมา `setData` จึงทับสถานะที่เพิ่งบันทึก ทำให้ดูเหมือน PATCH ไม่สำเร็จ
3. การ์ดไม่มีปุ่มลบ และ route `[id]` มีเฉพาะ PUT/PATCH จึงไม่มีเส้นทางลบให้ใช้งานจริง `AutoCommentJob.rule` ใช้ FK แบบ Restrict จึงไม่ควรลบแถวกฎที่มีประวัติงานอ้างอยู่

## การพิสูจน์

- jsdom test สร้างชุด unbound แล้วตรวจว่าสวิตช์ต้องกดได้ ก่อนแก้ได้ `disabled=true` ขณะที่ bound-rule differential ใช้ handler และ transport เดียวกันผ่าน จึงแยกสาเหตุไปที่เงื่อนไข unbound
- อีก test หน่วง GET เก่า กดปิดชุดให้ PATCH สำเร็จ แล้วปล่อย GET เก่า ก่อนแก้ได้ `aria-checked=true` ทั้งที่ค่าสุดท้ายต้องเป็น false หากไม่มี GET ซ้อน test ของสวิตช์ผ่าน
- ไล่ source พบว่าไม่มี DELETE export และปุ่มลบ ไม่ใช่ปัญหาการส่งคำขอไปฐานข้อมูล

## การแก้ไข

- สวิตช์เก็บ enabled ที่เจ้าของต้องการได้ แม้ยังไม่พร้อมส่ง UI แสดง **เปิดไว้ · รอความพร้อม** แยกจากการส่งจริง
- Worker เลือกเฉพาะกฎที่ยินยอมและผูกบัญชี/อุปกรณ์ไม่ว่าง เส้นทางส่งยังตรวจบัญชี อุปกรณ์ สิทธิ์ โควตา กลุ่มและสถานะหยุดงาน ไม่อนุญาตส่งเพียงเพราะเปิดสวิตช์
- `reloadSequence` เพิ่มลำดับก่อน mutation และก่อนโหลดข้อมูล ผลตอบกลับที่เก่ากว่าจะไม่เรียก `setData` ทับผลล่าสุด ไม่ข้ามการ reload หลังบันทึก
- DELETE เก็บ `auto_comment_rule_deleted_<id>` ใน Setting พร้อมปิดกฎ เพิ่ม revision ยกเลิกงานที่ยังไม่ส่ง และบันทึก log ภายใน control lock งาน `sending` ข้อความสำเนาและประวัติ unique dispatch ยังคงอยู่
- dashboard กรองรายการลบแล้วออก ไม่นับรายการที่ลบในเพดาน 30 ชุด และปฏิเสธการเปิด/เขียนทับกฎที่ลบแล้วผ่าน URL เดิม

## เหตุที่การทดสอบเดิมไม่พบ

การทดสอบเดิมยืนยันว่าฉบับร่างต้องล็อกสวิตช์ จึงรับรองเงื่อนไขที่ไม่ตรงการใช้งานที่เจ้าของต้องการ ไม่มี test หน่วง GET ข้าม PATCH และไม่มี flow ลบชุด เพิ่ม regression ครอบคลุมทั้งสามกรณีแล้ว

## การตรวจสอบ

`TEST_DATABASE_URL` ชี้ PostgreSQL ทดสอบที่ `127.0.0.1:55439` เท่านั้น แต่ละ suite ใช้ `test_*` schema และลบ schema หลังจบ `npm run test:ci` ผ่าน 677 tests ใน 77 files รวมการรักษางานที่เริ่มส่งแล้ว การยกเลิกงานค้าง stale revision การห้ามเปิดรายการลบแล้ว และการคืนพื้นที่เพดานรายการ

UI regressions ที่เคย fail ผ่านหลังแก้ ตรวจ lint และ build แล้ว ไม่ส่งคอมเมนต์ Facebook จริง ไม่ทดสอบด้วยการกดปุ่มส่งบน Facebook และไม่เปลี่ยนกฎหรือสวิตช์จริงของเจ้าของเพื่อทดลอง
