# เปิดและดูแลบอทในจอเสมือน — 1.11.18

เป้าหมายคือเก็บโพสต์ต่อเนื่องโดยไม่บังจอเจ้าของ ไม่ต้องเปิดเว็บและจอเสมือนทีละคำสั่ง AI ยังคงเป็นงานเสริมบน worker โฮสต์เดิม ไม่มีการเพิ่ม worker ในเครื่อง เปลี่ยนโควตา หรือเปิดสิทธิ์คอมเมนต์

## เริ่ม/ตรวจ/หยุด

หลังติดตั้งตาม [คู่มือจอเสมือน](SINGLE-PC-BOT.th.md) และ build สำเร็จ รันใน WSL:

```sh
npm run bot:start
npm run bot:status
```

คำสั่งเริ่มเปิดตัวควบคุมเบื้องหลัง ปิด terminal ได้ เว็บอยู่ http://localhost:8001 และ viewer อยู่ http://localhost:6085/vnc.html?host=localhost&port=6085&resize=scale ปิดหรือย่อ viewer ได้โดยไม่ย่อ Chromium ภายในจอ ต้องให้ Windows/WSL ตื่นอยู่

ถ้าเว็บหรือจอเสมือนเปิดอยู่แล้ว ตัวควบคุมจะรายงาน `existing` และเฝ้าดูโดยไม่ยึดสิทธิ์หยุดโปรเซสนั้น หากเว็บเดิมหายและพอร์ตว่างจึงเริ่มเว็บใหม่ให้ เว็บที่ตัวควบคุมเปิดเองจะลองใหม่เมื่อโปรเซสล้มด้วย backoff 3 วินาทีถึง 5 นาที หรือเมื่อ health ไม่ผ่าน 3 ครั้งติดหลังให้เวลาเริ่ม 60 วินาที จะรีสตาร์ตเฉพาะเว็บ ไม่ฆ่าบริการอื่นที่ครองพอร์ต 8001

```sh
npm run bot:stop
```

ตัวควบคุมรับคำสั่งใน 15 วินาที หยุดเฉพาะบริการที่ตนเปิด ไม่ปิด Chrome ส่วนตัวหรือบริการ `existing` ก่อนหยุดให้พักงานและตรวจงานส่งตามปกติ ไม่รับประกันยกเลิก click ที่ได้รับสิทธิ์ไปแล้วทันที

## เริ่มอัตโนมัติ

เครื่องที่มี systemd user bus ใช้:

```sh
npm run bot:install-service
```

ติดตั้ง user service ชื่อ `mybot-workstation.service` เปิดเว็บ/จอเสมือนเมื่อ user manager เริ่ม และกู้ supervisor หากล้ม โดยไม่เปิด lingering หรือแก้บริการ OS ต้องหยุด supervisor แบบ standalone เดิมก่อนติดตั้ง ไม่หยุดโปรเซสอื่นที่อาจเปิดเว็บหรือเบราว์เซอร์ไว้แล้ว

สำหรับ Windows ให้ติดตั้ง launcher เพิ่มเพื่อเปิด WSL เมื่อเจ้าของล็อกอิน Windows รัน PowerShell (แทนค่าชื่อ distro/path ตามเครื่อง):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\install-wsl-workstation.ps1 -Distro "kali-linux" -Repo "/home/supersix/my-bot/projects/my-bot"
```

สร้างเฉพาะ `Startup\MY-BOT-WSL.vbs` ซึ่งเรียก user service ไม่เริ่ม worker และไม่แก้ `MY-BOT.vbs` รุ่นเก่า หากพบ launcher เก่าต้องตรวจเพื่อไม่ให้เปิดบริการซ้อน เริ่มเมื่อ logon ไม่ใช่ก่อนเข้าสู่ Windows ไม่เปลี่ยน sleep/audio settings

ถอนด้วย `npm run bot:uninstall-service` ใน WSL และ `scripts\windows\uninstall-wsl-workstation.ps1` ใน PowerShell ไม่ลบโปรไฟล์หรือข้อมูลค้าง

## การฟื้นตัวและข้อจำกัด

- noVNC/x11vnc/Openbox ล้ม: supervisor จอเสมือนรุ่นนี้กู้เฉพาะโปรเซสที่ตนสร้างสูงสุด 5 ครั้ง พร้อม backoff โดยไม่เปิด Chrome ใหม่ หากเกินจำนวนจะเก็บ Chrome ไว้และรายงาน `review`
- Chromium/Xvfb ล้ม: เก็บสถานะรอตรวจ ไม่เปิดเบราว์เซอร์ซ้ำอัตโนมัติ เพราะอาจมีผลส่งคอมเมนต์ที่ไม่แน่นอน เมื่อตรวจประวัติและบัญชีแล้วใช้ `npm run bot:resume-desktop` ไม่แก้หรือส่งซ้ำงาน uncertain
- ติดตั้งขณะมีจอเสมือนรุ่นเก่ารันอยู่: รายงาน `existing` การกู้ viewer แบบใหม่จะมีผลเมื่อเจ้าของปิดจอเดิมอย่างปลอดภัยและเปิดผ่าน supervisor รุ่นใหม่ ไม่รีสตาร์ต session ให้เงียบ ๆ
- เน็ตหลุด: ส่วนขยายเก็บ outbox/recovery และลองใหม่ตามรอบเดิม ยอมรับเฉพาะ receipt จากเซิร์ฟเวอร์ ไม่ล้างข้อมูลเมื่อ timeout ใช้ชุดทดสอบ synthetic ยืนยันการกู้ข้าม Chrome restart ไม่อ้างว่าไม่มีโอกาสสูญเสียหาก storage หรือดิสก์เสีย
- MV3 ตื่นใหม่: ตรวจชื่อและ period ของ alarm อ่านโพสต์/งาน/heartbeat แล้วเติมเฉพาะตัวที่ขาด โดยไม่แตะ alarm นัดอ่านต่อหรือช่วงพัก
- Watchdog แยกการพักที่เจ้าของตั้งไว้จากปัญหา ตรวจข้อมูล runtime ที่ตรง install/version และใหม่ไม่เกิน 3 นาที หาก Facebook ตรวจพบว่าหลุดล็อกอิน โพสต์รอส่งเกิน 15 นาที หรือแหล่งเลยกำหนดและไม่มีรอบอ่านเกิน 15 นาที จะขึ้นปัญหาในภาพรวม แจ้งภายนอกเฉพาะช่องทางที่เจ้าของเปิดไว้ หลังพบปัญหาสองรอบและตามช่วงเตือนเดิม ไม่ส่งทดสอบจริงในงานนี้
- การอ่านวนข้ามแหล่งและการคืนแท็บใช้ scheduler/checkpoint/ownership เดิม ไม่มีการเพิ่มแท็บหรือยก quota เพื่อเร่งความเร็ว

## บันทึกและตรวจรับ

`npm run bot:status` แสดงเว็บ/VNC และสถานะล่าสุด ไม่แสดง token/cookie/password standalone log อยู่ `data/workstation.log` สำหรับ user service ดู `journalctl --user -u mybot-workstation.service` สถานะส่วนประกอบอยู่ใน `data/bot-desktop/` ที่ถูก ignore ไม่ส่งโฟลเดอร์นี้ให้ผู้อื่น

อัปเดตเว็บและส่วนขยายให้เป็น 1.11.18 พร้อมกัน ไม่ต้อง migrate ฐานข้อมูล ใน Chromium จอเสมือน Reload ส่วนขยายหนึ่งครั้งเมื่อพักงานอย่างปลอดภัยแล้ว ตรวจ version และการเชื่อมต่ออีกครั้ง

ตรวจรับจริงอย่างน้อย 30 นาที: ปิด viewer แล้วดูจำนวนโพสต์เพิ่ม ความคืบหน้าทุกแหล่ง จำนวนข้อมูลค้างและ heartbeat ทดสอบตัด/คืนเครือข่ายเฉพาะช่วงที่ไม่มีงานส่งคอมเมนต์ ไม่ถือว่า heartbeat หรือชุดทดสอบ synthetic เพียงอย่างเดียวยืนยันความเร็ว Facebook จริง

## ผลตรวจการแก้ไข

วันที่ 9 พฤศจิกายน 2026: ทดสอบผ่าน 868/868 ข้อ รวม 98 ไฟล์ โดยกำหนด TEST_DATABASE_URL เป็น PostgreSQL ชั่วคราวบน loopback พอร์ต 55439 แล้วปิดหลังตรวจ ไม่ใช้ฐานข้อมูลจริงในการทดสอบ `npm run build`, JavaScript/shell syntax และ `git diff --check` ผ่าน สคริปต์ PowerShell ใหม่เป็น ASCII และติดตั้ง Windows logon launcher สำเร็จ ติดตั้ง systemd user service แล้ว สถานะเว็บ/VNC พร้อมใช้งานและกำลังเฝ้าบริการเดิม (`existing`) โดยไม่ปิด Chromium ของเจ้าของ

พบและแก้ข้อผิดพลาดสองจุดจากการทดสอบ: alarm เดิมดูจำนวนรวมจึงไม่เติมตัวอ่านที่หายเมื่อมี alarm อื่นอยู่ครบสามตัว; systemd ไม่รับเครื่องหมายคำพูดเป็นส่วนหนึ่งของค่า WorkingDirectory จึงแยกรูปแบบ path setting ออกจาก ExecStart ที่ต้อง quote เพิ่ม regression ทั้งสองกรณี พร้อมทดสอบไม่สร้างโปรเซสใหม่หลังเริ่ม shutdown

ยังไม่ถือว่าได้ทดสอบ Facebook ต่อเนื่อง 30 นาทีบนโค้ดใหม่ ไม่ส่งคอมเมนต์จริง ไม่เปลี่ยนบัญชี/โควตาหรือ reset งานเก่า ส่วนการเผยแพร่ Render และการ Reload ส่วนขยายต้องทำแยกจากการติดตั้งบริการในเครื่อง
