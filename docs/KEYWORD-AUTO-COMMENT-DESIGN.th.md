# ออกแบบคอมเมนต์อัตโนมัติตามคำสำคัญ

วันที่ตรวจ: 8 พฤศจิกายน 2026 — ตรวจโค้ดใน workspace และทดสอบจำลอง ไม่ได้ตรวจการตั้งค่า production หรือส่งคอมเมนต์จริง

## ผลการปรับหน้าใช้งานตามคำสั่งล่าสุด

ปรับหน้า Auto Comment ใน workspace แล้ว: กฎใหม่และกฎที่เจ้าของเลือกแก้ไขแล้วบันทึกจากหน้านี้ใช้ keyword + template + Extension โดย requireAi=false เพิ่มตัวแก้ข้อความแยกใบ สูงสุด 30 ข้อความ ตัวกรองประวัติงาน และคำอธิบายเส้นทางบอท กฎเดิมบนเซิร์ฟเวอร์ยังไม่ถูกเปลี่ยนเอง หน้าจอแจ้งเมื่อมีกฎเดิมที่ใช้ AI/เจตนา/ช่องทางเดิม

ทดสอบรวมหลังปรับครั้งแรก: 503 ผ่าน, 88 ข้าม และ production build ผ่าน ตรวจ Chrome ด้วย API จำลอง: เพิ่ม/ลบข้อความและบันทึกกฎไม่รอ AI ผ่าน หน้าจอมือถือ 390px ไม่ล้น ไม่มี page error ยังไม่ได้ deploy หรือทดสอบส่งจริงบน Facebook ข้อเสนอในส่วนถัดไปเป็นที่มาของแบบ ไม่ใช่รายการที่ทำครบทั้งหมดแล้ว

## พฤติกรรมที่ต้องการ

โพสต์ใหม่ที่ระบบอ่านพบและตรงกฎเข้าสู่คิวโดยอัตโนมัติ ส่งหนึ่งคอมเมนต์ต่อโพสต์ในกลุ่มที่เจ้าของอนุญาต ผ่านบัญชีและอุปกรณ์ที่ผูกไว้ ใช้ข้อความสำเร็จรูปได้โดยไม่รอ AI

คำว่า “ทุกโพสต์” หมายถึงทุกโพสต์ที่ระบบอ่านพบและผ่านเงื่อนไข ไม่รับรองว่าจะอ่านพบทุกโพสต์บน Facebook หรือส่งได้ทันก่อนโพสต์หมดอายุ หากโพสต์เข้ามากกว่าเพดานส่ง งานจะสะสมและบางงานอาจหมดอายุ

## ผลตรวจระบบเดิม

| สิ่งที่ตรวจ | ผลจากโค้ด |
| --- | --- |
| จับคำสำคัญ | `src/lib/auto-comment/matching.ts` รองรับ any/all และคำยกเว้น แยกด้วยจุลภาคหรือขึ้นบรรทัดใหม่ ใช้ข้อความที่ normalize แล้วตรวจ substring |
| ไม่พึ่ง AI | ตั้ง `intentMode=keyword`, `requireAi=false`, `messageMode=template` ได้ |
| ค่าเริ่มต้นหน้าฟอร์ม | `src/app/(app)/auto-comment/page.tsx` ตั้ง buyer และ requireAi=true จึงไม่ใช่ค่าเริ่มต้นที่ตรงกับความต้องการนี้ |
| ประเมินต่อเนื่อง | Worker เรียก autoCommentTick ทุก 3 วินาทีเมื่อได้ lease; `browser.ts` ประเมินครั้งละไม่เกิน 100 โพสต์ และเตรียมครั้งละ 50 งาน ช่วงเวลานี้ไม่ใช่ SLA การส่ง |
| กันซ้ำ | live key ต่อโพสต์ข้ามกฎ เลือกกฎตาม priority; ไม่ควรล้างประวัติเพื่อส่งซ้ำ |
| ข้อความไม่ครบ | รอ full text ก่อน ไม่ส่งจากข้อความที่ truncated |
| เวลาเริ่ม | รับเฉพาะโพสต์หลัง Start และไม่ย้อนหลังไปส่งโพสต์ที่เผยแพร่ก่อน Start |
| โควตา | พักเมื่อถึงเพดานชั่วโมง/วันหรือ cooldown กลุ่ม และตรวจอายุโพสต์ก่อนส่งอีกครั้ง |
| ผลส่งคลุมเครือ | uncertain พักให้ตรวจเอง ไม่ส่งซ้ำอัตโนมัติ |

## แบบที่แนะนำ

ใช้คิวเดิม ไม่เพิ่มระบบส่งอีกชุด:

1. ส่วนขยายอ่านโพสต์ → บันทึก/กันโพสต์ซ้ำ → Worker ประเมินกฎ
2. ตรวจกลุ่มที่อนุญาต ข้อความครบ อายุโพสต์ เวลาเปิดทำงาน คำต้องห้าม โฆษณา และโพสต์ที่ข้ามไว้
3. จับคำสำคัญ เลือกกฎที่ priority สูงสุดที่ใช้ได้ แล้วเลือกข้อความสำเร็จรูป
4. บันทึกงานถาวร → รอโควตา/อุปกรณ์ → ตรวจข้อมูลและสิทธิ์ซ้ำก่อนส่ง
5. ส่วนขยายเปิดโพสต์และส่งผ่าน UI ที่ระบุเป้าหมายได้แน่นอน
6. บันทึกพบคอมเมนต์ในหน้าจอ หรือผลคลุมเครือแยกกัน ไม่อ้างว่า DOM observation คือการยืนยันจาก Meta

ไม่ต้องใช้ AI ในเส้นทางหลักนี้ AI เป็นตัวเลือกของกฎที่ต้องตีความเจตนาหรือร่างข้อความเท่านั้น

## ค่ากฎเริ่มต้นที่เสนอ

| ค่า | ข้อเสนอ |
| --- | --- |
| ประเภท | คำสำคัญล้วน + ข้อความสำเร็จรูป ไม่รอ AI |
| กลุ่ม | เลือกเฉพาะกลุ่มที่เจ้าของอนุญาตให้ส่ง |
| คำสำคัญ | ต้องระบุอย่างน้อยหนึ่งคำสำหรับรูปแบบนี้; ระบบเดิมยอมให้ว่างซึ่งจะไม่กรองด้วยคำสำคัญ |
| การจับคู่ | any หรือ all พร้อมตัวอย่างผลก่อนบันทึก |
| คำยกเว้น | เจ้าของกำหนด เช่น “ได้แล้ว”, “ปิดรับ”; ต้องลองกับข้อความจริง เพราะ substring อาจจับบริบทผิด |
| ข้อความ | เจ้าของตรวจและกำหนดเอง ไม่สร้างข้อเสนอ ราคา หรือลิงก์ขึ้นมา |
| อายุโพสต์ | เริ่มทดสอบที่ 24 ชั่วโมง ปรับให้ตรงความต้องการ |
| เพดานเริ่มต้น | คงค่าเดิม 5 ครั้ง/ชั่วโมง, 20 ครั้ง/วัน และพักกลุ่ม 300 วินาทีระหว่างทดสอบ ไม่ใช่การรับรองว่าแพลตฟอร์มอนุญาตปริมาณนี้ |
| เปิดใช้งาน | เริ่ม Dry Run ก่อน ไม่แปลงงานจำลองเป็นงานส่งจริง |

## งานปรับปรุงที่ควรทำตามลำดับ

1. เพิ่มปุ่มสร้างกฎ “คำสำคัญ ไม่รอ AI” ที่ตั้งสามค่าข้างต้นให้ครบ โดยคงกฎเดิมตามที่เจ้าของเลือกไว้ ปฏิเสธคำสำคัญว่างเฉพาะรูปแบบนี้
2. แสดงเหตุผลของแต่ละโพสต์ให้ชัด: ตรงกฎ, ไม่ตรง, รอข้อความเต็ม, รอ AI, รออุปกรณ์, รอโควตา, หมดอายุ, กันซ้ำ, ผลไม่ชัดเจน สถานะ pending_ai ปัจจุบันยังใช้เตรียมงาน template ด้วย จึงควรแสดงข้อความตามเหตุจริง
3. เพิ่มภาพรวม “ประเมินแล้ว/ตรงกฎ/รอส่ง/พบคอมเมนต์/หมดอายุ/uncertain” พร้อมอายุงานเก่าสุด และเตือนเมื่ออัตราโพสต์ตรงกฎเกินกำลังส่ง ไม่เพิ่มเพดานอัตโนมัติ
4. ทดสอบหลายกฎชนกัน คำไทย/อังกฤษ คำยกเว้น full-text ล่าช้า รีสตาร์ต และเพดานส่งด้วย mock และ TEST_DATABASE_URL เท่านั้น
5. ตรวจหน้า Facebook ของบัญชีจริงแบบไม่กดส่งก่อน การทดสอบ selector ด้วย HTML สังเคราะห์ยังไม่พิสูจน์ว่า UI จริงรองรับ

## หลักฐานและข้อจำกัด

คำสั่งที่รัน:

```powershell
npm.cmd test -- tests/pipeline/auto-comment.test.ts tests/pipeline/auto-comment-source.test.ts tests/pipeline/browser-comments-db.test.ts tests/extension/browser-comment.test.ts
```

ผล: 40 ผ่าน, 25 ข้าม การทดสอบ DB ข้ามเพราะไม่มี TEST_DATABASE_URL; ไม่ใช้ production เป็นฐานทดสอบ การทดสอบ UI ส่งใช้ DOM สังเคราะห์ ไม่มีการส่งจริง ไม่เปลี่ยนกฎหรือเริ่ม automation บน production

การปรับรอบนี้เปลี่ยนหน้าจอและค่ากฎที่ส่งเมื่อเจ้าของบันทึก ไม่ย้ายกฎเดิมหรือเปลี่ยนกลไกส่ง ต้องอนุมัติการส่งจริงแยกตาม AGENTS.md ก่อนทดสอบส่งจริง เก็บการกันซ้ำ durable journal โควตา และการหยุดเมื่อ checkpoint ไว้ทั้งหมด สิทธิ์กดที่ออกก่อน Stop อาจยังทำงานได้ไม่เกิน 3 วินาที
