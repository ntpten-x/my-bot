# ปรับความเสถียรการอ่านโพสต์และคิวคอมเมนต์ — 1.11.14

รุ่นปัจจุบัน **1.11.15** รวมการแก้ในเอกสารนี้และเพิ่มการแก้แท็บค้าง ดู [การปิดแท็บบอท](BOT-TAB-CLEANUP.th.md) ตัวเลข/เวลาเก็บสถิติด้านล่างเป็นบันทึกรอบ 1.11.14 ไม่ใช่ผลครบ 24 ชั่วโมงของรุ่นใหม่

## สิ่งที่แก้

### อ่านเนื้อหาเต็มด้วยเวลาที่เหลือของรอบ

เดิม `cycle` ตรวจเพียงว่ายังไม่ครบ 3 นาที แล้วให้งบ `processFullTextQueue` ใหม่อีก 20–60 วินาที ส่วน `readFullTexts` ตั้งเวลาใหม่ 30 วินาทีต่อการเรียก การโหลดหน้าและส่ง outbox ยังรอแยกจากงบดังกล่าว กลุ่มที่รออยู่จึงเริ่มช้ากว่ากำหนดได้

รุ่นนี้เริ่ม deadline ของรอบก่อนขอ config และใช้ deadline เดียวกันครอบงานอ่านเต็มทั้งก่อนและหลัง discovery คิวเลือกเวลาที่น้อยกว่าระหว่างงบตัวเองกับเวลาที่เหลือ แล้วส่งต่อให้การนำทาง รอหน้า โหลด reader script อ่าน DOM และ flush outbox หมดเวลาจะไม่เริ่มงานอ่านรายการถัดไป

การรอ Chrome มี host timeout แต่ไม่ยกเลิกคำสั่งที่ Chrome รับไปแล้ว จึงไม่รับประกันว่าจะไม่มีงานอ่านที่รับไปก่อนหน้าทำต่อ การบันทึก checkpoint และการเก็บกวาดแท็บยังต้องทำเพื่อรักษาการกู้คืน ไม่ถือ deadline เป็นเหตุให้ลบข้อมูลค้าง

แก้ลำดับการเก็บข้อมูลด้วย: อ่านเนื้อหาเต็มแล้วต้องเข้าคิวส่งแบบ durable สำเร็จก่อนลบรายการ recovery ถ้า storage เต็มหรือ enqueue ไม่สำเร็จจะยังเก็บรายการไว้ ถ้าเน็ตหลุดหลัง enqueue เนื้อหาเต็มอยู่ใน outbox และรอ receipt ตามเดิม ไม่ส่งงานอ่านข้ามเซิร์ฟเวอร์

### ลดการโหลด templates ในแต่ละโพสต์

เดิมทุกโพสต์โหลดกฎพร้อม templates ใหม่ขณะถือ control lock รุ่นนี้โหลด snapshot ภายในรอบสแกน แล้วตรวจรายการกฎที่ยังใช้งานได้แบบเลือกเฉพาะ `id`, `revision`, `nextTemplate` ภายใต้ล็อกทุกโพสต์

เมื่อเพิ่ม ลบ ปิด เปลี่ยนลำดับ แก้ข้อความ หรือถอน consent จนรายการ/รุ่นของกฎเปลี่ยน จะโหลด snapshot ใหม่ก่อนประเมินโพสต์นั้น ตัวนับสลับข้อความอ่านใหม่ทุกโพสต์ จึงไม่ใช้ข้อความแรกซ้ำเพราะ cache ไม่เก็บ cache ข้ามรอบ และ `claim`/`authorize` ยังตรวจข้อมูลล่าสุดตามเดิม

เพิ่ม metric `comment_scan_rules` สำหรับเวลาการตรวจและ refresh กฎ อ่านร่วมกับ `comment_scan_lock` และ `comment_scan_transaction` จาก worker log ก่อนตัดสินใจขยาย batch หรือเพิ่มความถี่ ตัวอย่างเวลาเก็บไม่เกิน 200 ค่า ไม่มีข้อความโพสต์หรือ secrets

## หลักฐานทดสอบ

- Regression ก่อนแก้ยืนยันว่า budget 15 วินาทีปล่อยงานอ่านไปถึง 30 วินาที, ไม่สนใจ parent deadline, เริ่มอ่านแม้ parent หมดเวลา, ลบ recovery ก่อน enqueue ที่ล้มเหลว และรอ navigation ที่ไม่ตอบจน test timeout
- หลังแก้กรณีดังกล่าวผ่าน รวมการรอ Chrome ไม่ตอบและการอ่าน permalink ที่ตรงเป้าหมาย
- ตัวจำลองรอบหลักทดสอบทั้ง 3 และ 4 กลุ่มพร้อมงานอ่านเต็มท้ายรอบ โดยใช้งบรวม 3 นาที
- PostgreSQL ทดสอบแยกยืนยันการสลับข้อความ 6 โพสต์และการเปลี่ยน templates/ถอน consent ระหว่างสแกน ไม่มีการโหลด templates ซ้ำใน transaction แต่ละโพสต์เมื่อ revision ไม่เปลี่ยน
- ทดสอบ offline/restart/receipt/lease/quota/uncertain เดิมยังอยู่ในชุดทดสอบทั้งหมด ไม่มีการส่งคอมเมนต์จริงในการตรวจนี้

## เก็บสถิติต่อเนื่อง

ใช้ฐานข้อมูลที่ต้องการสังเกตใน `.env` ไม่แสดงหรือส่ง connection string ในแชต เครื่องมือนี้ใช้ read-only transaction ไม่เริ่ม collector, worker หรือคอมเมนต์

```powershell
npm.cmd run observe:automation -- --hours=24 --interval-seconds=60
```

ได้ไฟล์ `data/automation-observation-<timestamp>.jsonl` และเมื่อจบ/หยุดด้วย Ctrl+C จะเขียนไฟล์ชื่อเดียวกันลงท้าย `.summary.json` ทั้งสองไฟล์ถูก gitignore เก็บตัวอย่างสุดท้ายหลังครบเวลาที่ขอด้วย

ดูสรุปจากไฟล์ระหว่างรันหรือภายหลัง โดยไม่ต้องต่อฐานข้อมูล:

```powershell
npm.cmd run observe:automation -- --summary=data/automation-observation-<timestamp>.jsonl
```

สรุปแสดงเวลาที่เก็บจริง จำนวนครั้งที่อ่านสำเร็จ/ล้มเหลว ช่องว่างนานที่สุด จำนวนกลุ่มเกินกำหนดและคิวค้างสูงสุด จำนวนโพสต์/ผลคอมเมนต์ล่าสุด และ latency แต่ละขั้น ค่า cumulative ไม่ถูกบวกซ้ำทุกนาที

`coverageComplete` หมายถึงเก็บครบช่วงเวลาโดยไม่พบ sample error หรือช่องว่างเกินเกณฑ์ (2 เท่าของ interval + 15 วินาที) ไม่ใช่ใบรับรองว่าระบบเสถียร ต้องตรวจ `noCurrentExtensionSamples`, `latestOnlineVersions`, ปริมาณงานจริง, error และ latency ประกอบ เมื่อไม่มี heartbeat ของรุ่นปัจจุบัน คิวจะแสดงไม่ทราบ ไม่ใช่ศูนย์ ถ้าไม่มี `browser_observed` จะยังวัดเวลาส่งคอมเมนต์จริงไม่ได้ DOM observed ไม่ใช่ผลยืนยันจาก Facebook API

## นำไปใช้งาน

อัปเดตเว็บ/worker และ Reload ส่วนขยายให้เป็น **1.11.14** พร้อมกัน ไม่มี migration ใหม่ ไม่เปลี่ยน consent, Start, อุปกรณ์/บัญชีที่ผูก, โควตา หรือสถานะคอมเมนต์ หากระบบใช้งานอยู่บนอีกเครื่องหรือ Render ต้องนำโค้ดนี้ไปติดตั้งก่อนจึงจะเป็นผลหลังแก้ การเก็บก่อนอัปเดตเป็นเพียง baseline

ควรตรวจรายงานครบ 24 ชั่วโมงหลังอัปเดตจริง รวมคิวหลังเน็ตหลุดและ Chrome restart โดยเริ่มจากการอ่านโพสต์ การทดสอบส่งคอมเมนต์จริงต้องขออนุมัติแยก
