# คอมเมนต์อัตโนมัติตามประเภท

เปิด **คอมเมนต์อัตโนมัติ** (`/auto-comment`) เพื่อสร้างชุดตั้งค่าตามประเภทที่มีในหน้า **จัดการกลุ่ม** เช่น เกม / Roblox

## ขั้นตอน

1. เลือกประเภท ระบบแสดงข้อความจาก **จัดการข้อความ** ที่ใช้กับประเภทนั้น รวมข้อความที่ใช้ทั้งหมวดหมู่
2. เลือกข้อความได้หลายชุด (สูงสุด 30) และเลือกวิธี **สุ่ม**, **วนตามลำดับ**, หรือ **ใช้ข้อความเดียว** ระบบใช้หนึ่งข้อความต่อโพสต์ ไม่ได้ส่งทุกข้อความในโพสต์เดียว การสุ่มอาจได้ข้อความเดิมติดกัน
3. ตรวจกลุ่มที่อนุญาต แสดงเฉพาะกลุ่มในประเภทนี้ กลุ่มใหม่ที่เพิ่มภายหลังจะไม่เข้ากฎอัตโนมัติ ต้องกลับมาเลือกและบันทึกก่อน (สูงสุด 100 กลุ่ม)
4. ถ้าติดตั้งส่วนขยายแล้ว ให้เลือกบัญชี Facebook และอุปกรณ์/โปรไฟล์ Chrome ที่ใช้บัญชีนี้ หากยังไม่ติดตั้ง ให้เว้นสองช่องนี้และบันทึกฉบับร่างไว้ก่อน ก่อนเปิดใช้งานต้องจับคู่อุปกรณ์ เลือกบัญชีที่ไม่ถูกหยุดงาน และเปิดรับคอมเมนต์ใน popup
5. ตั้งเวลา วันอนุญาต อายุโพสต์ และระยะพัก แล้วตรวจสิทธิ์ใช้บัญชีและกติกาของแต่ละกลุ่มก่อนยืนยัน
6. บันทึกกฎใหม่ในสถานะปิด ตรวจข้อความ กลุ่ม บัญชีและเงื่อนไขให้ครบ แล้วเปิดกฎและกด **เริ่มส่งจริง** ระบบนี้มีเฉพาะการคอมเมนต์จริง ไม่มีโหมดทดลอง

การตั้งค่าหรือบันทึกไม่ได้เริ่มส่งคอมเมนต์เอง ต้องกดเริ่มส่งจริง การทดสอบของนักพัฒนาใช้ mock และฐานข้อมูลทดสอบ ไม่ส่ง Facebook จริง

## ค่าเริ่มต้นสำหรับการเริ่มทดลอง

| ค่า | เริ่มต้น |
| --- | --- |
| วิธีเลือกข้อความ | สุ่มจากข้อความที่เลือก |
| ช่วงเวลา | ตลอด 24 ชั่วโมง (00:00–24:00) Asia/Bangkok |
| วันอนุญาต | ทุกวัน |
| อายุโพสต์สูงสุด | 6 ชั่วโมง |
| พักระหว่างคอมเมนต์ในกลุ่ม | 60 วินาที |
| คำยกเว้น | ขายแล้ว, ได้แล้ว, ปิดการขาย, ไม่หาแล้ว |
| คำที่ต้องพบ | เว้นว่างได้ เลือกทุกโพสต์ที่ผ่านเงื่อนไขอื่น |
| สถานะกฎใหม่ | ปิด |

เป็นค่าเริ่มทดลองที่ปรับได้ ไม่ใช่การรับประกันว่าปลอดภัยหรือเหมาะกับทุกกลุ่ม โควตารวมรายชั่วโมงและรายวันยังใช้ค่าที่เจ้าของตั้งไว้เดิม (ค่าเริ่มระบบใหม่ 50/ชั่วโมง และ 200/วัน) การแก้หน้านี้ไม่เปลี่ยนโควตาเดิม

ช่วงเวลาสิ้นสุดน้อยกว่าเริ่มหมายถึงข้ามคืน วันอนุญาตของช่วงข้ามคืนอิงวันที่ช่วงนั้นเริ่ม เช่น อนุญาตวันจันทร์ 22:00–02:00 ครอบคลุมอังคารก่อน 02:00 ด้วย อายุโพสต์และระยะพักตรวจซ้ำก่อนออกสิทธิ์ส่ง ไม่ใช้เฉพาะตอนสร้างคิว

## ความเชื่อมโยงข้อมูล

เซิร์ฟเวอร์ตรวจประเภทของกลุ่มและขอบเขตข้อความจากฐานข้อมูล ไม่เชื่อเนื้อหาหรือรายชื่อกลุ่มที่ไคลเอนต์ส่งมาอย่างเดียว บันทึกสำเนาข้อความลง `AutoCommentTemplate` พร้อมกฎ หากแก้ข้อความต้นฉบับใน `/messages` ต้องเปิดกฎแล้วบันทึกอีกครั้งจึงเปลี่ยนข้อความที่ใช้ส่ง การแก้กฎเพิ่ม revision และยกเลิกงานที่ยังไม่ส่งตามกลไกเดิม

การอ้างประเภทและรหัสข้อความเก็บใน `Setting` ชื่อ `auto_comment_type_setup_<ruleId>` และใช้ allowlist ของกฎเดิม ไม่เพิ่มตารางหรือ migration ระบบสำรองรวม Setting อยู่แล้ว และ restore ยังคงปิดระบบอัตโนมัติตามเดิม

Worker ตรวจว่ากลุ่มยังอยู่ในประเภทนั้นทั้งตอนประเมินโพสต์และก่อนออกสิทธิ์กดส่ง หากย้ายกลุ่มไปประเภทอื่น ลบประเภท หรือปิดประเภท จะไม่ส่งตามกฎเดิม รายงานผลทดลองกฎตรวจขอบเขตประเภทด้วย กฎเก่าที่ไม่ได้อ้างประเภทยังคงใช้ allowlist เดิมจนเจ้าของเลือกแก้ไขและบันทึกเป็นแบบใหม่

หยุดบัญชีหรือ Stop จะไม่อนุญาตงานส่งใหม่ แต่สิทธิ์ที่ออกแล้วอาจกดส่งได้ถึง 3 วินาที ผลส่งไม่ชัดเจนต้องตรวจเองและไม่ส่งซ้ำอัตโนมัติ ดู `BROWSER-COMMENTS.th.md` สำหรับข้อจำกัดทั้งหมด

## การเปลี่ยนจากระบบทดลองเดิม

หน้าใช้งานและ API ควบคุมมีเฉพาะการส่งจริง API ปฏิเสธการเปิด Dry Run การอ่านค่าหรือเปิดหน้าเว็บไม่เปลี่ยนระบบทดลองเก่าให้ส่งจริง และ Worker ปกติไม่ประมวลผลรอบทดลองเก่า เมื่อเจ้าของกดเริ่มส่งจริง ระบบออก generation ใหม่ ยกเลิกงานที่ยังค้างของรอบเดิม โดยไม่แปลงงานทดลองให้เป็นงานส่งจริง

กดบันทึกโควตาไม่เริ่มงาน ปุ่มพัก หยุด และหยุดฉุกเฉินยังคงอยู่ Restore กลับเป็นหยุดและ Emergency Stop โดยใช้โหมดส่งจริงที่ยังไม่เริ่ม ประวัติ/ตัวระบุ Dry Run เดิมเก็บไว้เพื่อความเข้ากันได้และการทดสอบ regression ภายใน ไม่ใช่ตัวเลือกของระบบใช้งาน

## ตั้งค่าก่อนติดตั้งส่วนขยาย

ไม่ต้องติดตั้งส่วนขยายเพื่อสร้างหมวดหมู่ ประเภท กลุ่ม ข้อความ และชุดตั้งค่าคอมเมนต์ สามารถเลือกประเภท ข้อความ กลุ่ม วันเวลา อายุโพสต์และระยะพัก แล้วเว้นบัญชี/อุปกรณ์และกด **บันทึกฉบับร่าง** ได้ ชุดที่ยังไม่ผูกบัญชีหรืออุปกรณ์ยังไม่สร้างคิว แม้เปิดสวิตช์ไว้และระบบส่วนกลางกำลังทำงาน

หลังติดตั้งและจับคู่ส่วนขยาย ให้ล็อกอิน Facebook แล้วเปิดแก้ไขฉบับร่างเดิม กด **ตรวจบัญชีและอุปกรณ์อีกครั้ง** เพื่ออัปเดตรายการโดยไม่ล้างค่าที่กรอก เลือกบัญชีและอุปกรณ์ ยืนยันสิทธิ์แล้วเปิดใช้งานและบันทึก ไม่มีการผูกบัญชีให้อัตโนมัติหรือเริ่มส่งเพราะติดตั้งสำเร็จ

บัญชี/อุปกรณ์ไม่จำเป็นสำหรับการตั้งค่าหรือเปิดสถานะไว้ล่วงหน้า แต่ก่อนรับงานและส่งจริงยังต้องมีอุปกรณ์ที่จับคู่ บัญชีที่ตรงกัน การอนุญาตใช้บัญชี และบัญชีไม่ถูกหยุดงานตามเดิม ถ้าระบบส่วนกลางกำลังทำงานอยู่ เมื่อเปิดใช้งานและบันทึกครบแล้ว กฎสามารถรับงานได้ตามเงื่อนไข หากระบบหยุดอยู่ต้องกดเริ่มส่งจริงด้วย

## รายการชุดคอมเมนต์ตามประเภท

หน้าแรกแสดงชุดที่บันทึกแล้วเป็นรายการแยกตามประเภท เช่น Roblox, ROV และคอม การ์ดแต่ละชุดแสดงหมวดหมู่ ประเภท จำนวนข้อความ วิธีเลือกข้อความ จำนวนกลุ่ม วันเวลา อายุโพสต์ ระยะพัก และบัญชีที่ผูกไว้

- **สร้างชุดคอมเมนต์** เปิดฟอร์มสร้าง เมื่อบันทึกแล้วปิดฟอร์มและกลับมาเห็นรายการทันที
- **แก้ไข** เปิดฟอร์มเดียวกับตอนสร้างพร้อมค่าที่บันทึกไว้ แก้ข้อความ กลุ่ม บัญชี หรือเวลาแล้วบันทึกกลับรายการเดิม
- **สวิตช์เปิด/ปิด** เปลี่ยนเฉพาะสถานะและ revision ของชุดนั้น ไม่แก้ข้อความสำเนา ไม่เปลี่ยนเวลา ไม่เปลี่ยนโควตารวมหรือปุ่มเริ่ม/หยุดส่วนกลาง
- ปิดชุดจะยกเลิกงานที่ยังไม่ส่งและถอน claim ของชุดนั้น โดยคงประวัติส่งและงานที่เริ่มส่งแล้วให้ตรวจผลตามเดิม
- ชุดที่ยังไม่ผูกบัญชี/อุปกรณ์หรือยังไม่ยินยอม เปิดปิดสวิตช์ได้เพื่อเก็บค่าล่วงหน้า เมื่อเปิดจะแสดง **เปิดไว้ · รอความพร้อม** และยังไม่ทำงาน ต้องแก้ไขผูกบัญชี/อุปกรณ์และยืนยันสิทธิ์ก่อน
- สวิตช์ไม่บังคับให้เบราว์เซอร์ออนไลน์เพื่อบันทึกสถานะ แต่ยังตรวจประเภทของกลุ่มและกฎที่ถูกพัก ส่วนการรับงาน/ส่งจริงตรวจบัญชี อุปกรณ์และสิทธิ์แยกต่างหาก หากมีการแก้ไขจากหน้าต่างอื่นจะให้รีเฟรชแทนการใช้ค่ารุ่นเก่า

หากระบบส่วนกลางกำลังทำงาน การเปิดชุดที่พร้อมแล้วอนุญาตให้รับงานตามเงื่อนไขทันที หากระบบส่วนกลางหยุดอยู่ สวิตช์เปิดชุดไม่กดเริ่มส่งแทนเจ้าของ ต้องกดเริ่มส่งจริงด้วย

## ลบชุดคอมเมนต์

ปุ่ม **ลบ** อยู่ในการ์ดแต่ละชุดและต้องยืนยันก่อนลบ ลบแล้วรายการหายและงานที่ยังไม่ส่งถูกยกเลิก งานที่เริ่มส่งแล้วและประวัติส่งยังอยู่เพื่อตรวจผล ไม่มีการส่งซ้ำอัตโนมัติ

เก็บสถานะลบใน `Setting` ชื่อ `auto_comment_rule_deleted_<id>` และปิดกฎพร้อมเพิ่ม revision ภายใน control lock ไม่ลบแถวที่ประวัติงานอ้างอยู่ รายการที่ลบไม่นับรวมเพดาน 30 ชุด และไม่สามารถเปิดใหม่หรือเขียนทับผ่าน URL เดิมได้ สถานะระบบส่วนกลางและโควตาไม่เปลี่ยน

## ประสิทธิภาพคิวในส่วนขยาย 1.11.4

อัปเดตเว็บแล้ว Reload ส่วนขยายเป็น 1.11.4 ระบบตรวจโควตา/ระยะพักก่อนเปิดแท็บ และรายงานผลครั้งเดียวในเส้นทางปกติ งานที่ยืนยันว่าไม่ได้เรียกปุ่มส่งแสดง **ไม่ได้เรียกปุ่มส่ง** โดยไม่พักระบบส่วนกลาง ผลที่คลุมเครือหลังเริ่มเรียก send ยังคงหยุดและไม่ส่งซ้ำอัตโนมัติ รายละเอียดและข้อจำกัดอยู่ใน `COMMENT-DELIVERY-EFFICIENCY.th.md`
