# อ่านฟีดแยกจากหน้าต่างที่เจ้าของใช้งาน — Extension 1.11.5

## การใช้งาน

หลังอัปเดตเว็บ ให้เปิด `chrome://extensions` แล้วกด Reload MY-BOT เป็น **1.11.6** ใน Chrome โปรไฟล์ที่จับคู่ไว้ เปิด Facebook และล็อกอินตามปกติ ไม่ต้องจับคู่ใหม่ ระบบเปิดหน้าต่าง Chrome ปกติสำหรับอ่านข้อมูลแยกโดย `focused: false` เจ้าของจึงอยู่หน้า MY-BOT ต่อได้ หน้าต่างนี้ใช้บัญชี Facebook ของ Chrome โปรไฟล์เดียวกัน

ปล่อยหน้าต่างบอทไว้โดยไม่ย่อทั้งบาน Chrome/Facebook อาจจำกัดการโหลดเมื่อหน้าต่างอยู่เบื้องหลัง ถูกบัง หรือย่อ การแก้นี้ไม่รับประกันว่า Facebook จะโหลดเท่ากับหน้าที่มีโฟกัส แต่จะไม่แก้ปัญหาการโหลดด้วยการแย่งแท็บเจ้าของ ปิดหน้าต่างบอทได้ ระบบเปิดใหม่เมื่อถึงรอบอ่านถัดไป ข้อมูลที่บันทึกลง outbox/จุดอ่านค้างยังใช้กลไกกู้คืนเดิม พักการอ่านได้จากป๊อปอัปส่วนขยาย

อย่าย้ายแท็บส่วนตัวเข้าไปในหน้าต่างบอท หากทำ ระบบจะเลิกสลับแท็บในหน้าต่างนั้น และสร้างหน้าต่างอ่านแยกสำหรับงานใหม่ โดยไม่ปิดหน้าต่างที่มีแท็บส่วนตัว เมื่อเจ้าของโฟกัสหน้าต่างบอท ระบบไม่สั่งสลับแท็บเพิ่ม ส่วนแท็บที่เปิดอ่านไว้ก่อนอัปเดตจะอ่านต่อแบบไม่สั่งเปิดแท็บในหน้าต่างเจ้าของจนจบรอบ

**ขอบเขต:** การแยกหน้าต่างนี้ครอบคลุมการอ่านกลุ่ม/Marketplace และโพสต์เพื่อดึงข้อมูล การส่งคอมเมนต์จริงผ่าน `comment-worker.js` ยังเปิดหน้า Facebook แบบมีโฟกัสเพื่อใช้ editor ตามข้อจำกัดเดิม ดู [การส่งคอมเมนต์ผ่านเบราว์เซอร์](BROWSER-COMMENTS.th.md) การอัปเดตไม่เปิดกฎหรือเริ่มส่งคอมเมนต์แทนเจ้าของ

## สรุปปัญหา

เจ้าของอยู่แท็บ MY-BOT แต่ถูกสลับไป Facebook ระหว่างอ่านฟีด แก้ใน working tree บน branch `master` ด้วยหน้าต่างอ่านแยกและตรวจสิทธิ์การสลับแท็บก่อนทุกครั้ง

## สาเหตุ

`ensureScrapeWindow()` เดิมเลือกหน้าต่าง Facebook ของเจ้าของ และ `openReader()` อาจยืมแท็บ Facebook ส่วนตัวที่ไม่ได้เปิดดู ขณะอ่าน `scrapeGroup()` เรียก `withReaderForeground()` สำหรับ deep/coverage หรือ `wakeReaderTab()` สำหรับปลุกหน้า ทั้งสองสั่ง `chrome.tabs.update(..., {active: true})` ในหน้าต่างเดียวกับ MY-BOT จึงเปลี่ยนแท็บที่เจ้าของเห็น แม้ตอนสร้างแท็บจะใช้ `active: false` แล้วก็ตาม การ restore แท็บเดิมหลังอ่านเสร็จยังอาจทับการเลือกแท็บใหม่ระหว่างรอ

## การแก้ไข

`ensureScrapeWindow()` สร้าง/นำกลับมาใช้เฉพาะหน้าต่าง `host: "reader"` แบบ normal, unfocused ไม่เปลี่ยนขนาด/ตำแหน่งหน้าต่างเจ้าของ ไม่ยืมหรือเปลี่ยน URL แท็บส่วนตัว `activateIsolatedReader()` ตรวจทั้ง ref, windowId จริงของแท็บ, รายชื่อแท็บที่เป็นของ collector, สถานะโฟกัสและ minimized ก่อนเปิดแท็บอ่าน ไม่ restore แท็บเจ้าของ ไม่สั่งโฟกัสหน้าต่าง และไม่คืนหน้าต่าง minimized เอง การอ่าน/เก็บจุดต่อ/outbox และเพดานสองงานอ่านพร้อมกันใช้ระบบเดิม

## การค้นพบและช่องว่างเดิม

จำลอง Chrome API ใน VM แล้วรันฟังก์ชันจริงจาก `background.js` พบว่าการ hold reader เปลี่ยน active tab ในหน้าต่างเจ้าของได้แน่นอนโดยไม่เกี่ยวกับ comment-worker การเปิดแท็บ `active: false` อย่างเดียวจึงไม่ใช่การป้องกันที่เพียงพอ เดิม regression test ตรวจรูปแบบ source ว่าเปิดแท็บเบื้องหลัง แต่ไม่ได้ตรวจ active tab ของเจ้าของตลอดการอ่าน และยังยืนยันสถาปัตยกรรมหน้าต่างเดียว

## การตรวจสอบ

`tests/extension/reader-focus.test.ts` ตรวจการอ่านแบบ hold/pulse, นำหน้าต่างเดิมกลับใช้, เปิดใหม่หลังปิด, ref จากรุ่นเก่า, แท็บที่ถูกย้ายเข้าหน้าต่างเจ้าของ, หน้าต่างที่มีแท็บส่วนตัว, การโฟกัส/ย่อหน้าต่างบอท และไม่ restore การเลือกแท็บเก่าทับเจ้าของ ชุด `continuous-reader.test.ts` ตรวจการอ่านต่อและเก็บข้อมูลเดิม

การทดสอบ Chrome API เป็นการจำลอง ไม่มีการเข้าถึง Facebook จริงหรือส่งคอมเมนต์จริง ยังต้องสังเกตอัตราการโหลดใน Chrome ของเจ้าของหลัง Reload ส่วนขยาย เพราะ Chrome/Facebook อาจ throttle หน้าต่างที่ไม่มีโฟกัสต่างกันตามเครื่อง

ผลตรวจรอบแก้ไข: `npm test` ผ่าน **700 tests / 78 files** โดยใช้ `TEST_DATABASE_URL` ของ Postgres ชั่วคราวแยกจากฐานข้อมูลเจ้าของ, `npm run build` ผ่าน และ `node --check extension/background.js` ผ่าน
