# วิธีติดตั้ง MY-BOT บนเครื่อง Windows ใหม่

เอกสารนี้พาตั้งแต่เครื่องเปล่าจนเปิดฟีดได้ คนเดียว ไม่มีค่าบริการรายเดือน ใช้ AI ฟรีได้ทั้งบนเครื่องและคลาวด์

คู่มือสั้นในแอปอยู่ที่หน้า **วิธีใช้** หลังเข้าสู่ระบบ เอเจนต์เขียนโค้ดที่เปิดรีโปนี้ให้อ่าน [AGENTS.md](../AGENTS.md) ที่รากโปรเจกต์ก่อนติดตั้งหรือแก้โค้ด

## สิ่งที่ควรมี

- Windows 10 หรือ 11
- Google Chrome
- อินเทอร์เน็ตตลอดเวลาที่ใช้งาน เพราะฐานข้อมูลอยู่บน Supabase และตอนติดตั้งต้องโหลด Node, โมเดล และแพ็กเกจ
- โปรเจกต์ Supabase (ฟรีก็พอ) ดูหัวข้อ "ฐานข้อมูล Supabase" ด้านล่าง
- แรม 16 GB ขึ้นไป ถ้าจะรันโมเดลบนเครื่อง การ์ดจออย่าง RTX 3060 (VRAM 12 GB) หรือเครื่องแรม 32 GB รัน `qwen2.5:7b` ได้สบาย ถ้า VRAM น้อยให้เลือก `qwen2.5:3b` ตอนสคริปต์ถาม

ไม่ต้องเป็นผู้ดูแลระบบก็ติดตั้งได้ส่วนใหญ่ ถ้า Task Scheduler ปฏิเสธ สคริปต์จะใช้โฟลเดอร์ Startup แทน

## 1. โคลนโปรเจกต์

ติดตั้ง Git จาก https://git-scm.com ถ้ายังไม่มี แล้วเปิด PowerShell

```powershell
git clone <ที่อยู่รีโปของคุณ> my-bot
cd my-bot
```

## 2. รันสคริปต์ติดตั้ง

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\setup.ps1
```

หรือหลังมี Node แล้ว

```powershell
npm run setup
```

สคริปต์ทำสิ่งเหล่านี้ตามลำดับ

1. ตรวจ Node.js 20 ถ้าไม่มีจะลองติดตั้ง LTS ด้วย winget
2. ตรวจ Git
3. `npm install`
4. คัดลอก `.env.example` เป็น `.env` ถ้ายังไม่มี
5. ถามคีย์ Groq, Gemini และ Discord webhook แบบไม่แสดงตัวอักษร กด Enter เพื่อข้ามได้
6. ถ้า `.env` ยังไม่มีฐาน Supabase จะถามสตริง Transaction pooler กับรหัสผ่านฐาน (ไม่แสดงตัวอักษร) แล้วเขียน `DATABASE_URL` กับ `DIRECT_URL` ให้
7. `npx prisma migrate deploy` และ seed หมวดกับโทเคนส่วนขยาย
8. ติดตั้ง Ollama ถ้ายังไม่มี แล้วเลือกพอร์ตที่ Windows ไม่ได้กันไว้
9. ตั้ง `OLLAMA_HOST` ของผู้ใช้ เปิด `ollama serve` แล้วดึงโมเดลแชทกับ `bge-m3`
10. เขียน `OLLAMA_BASE_URL` ลง `.env`
11. `npm run build`
12. ถามว่าจะเปิดอัตโนมัติตอนล็อกอินหรือไม่
13. พิมพ์โทเคนส่วนขยายและวิธีโหลดใน Chrome

พอร์ตเว็บคือ **8001** เสมอในค่าเริ่มต้น

### ฐานข้อมูล Supabase

ข้อมูลทั้งหมด (โพสต์ หมวด การตั้งค่า แจ้งเตือน) เก็บใน Postgres ของ Supabase ผ่าน Prisma

1. สร้างโปรเจกต์ที่ https://supabase.com เลือกภูมิภาคสิงคโปร์จะเร็วสุด จดรหัสผ่านฐานไว้
2. กด Connect > Connection string > Transaction pooler คัดลอกสตริงพอร์ต 6543 ไว้ตอบสคริปต์
3. ถ้าจะใส่เองใน `.env` ให้มีสองบรรทัด
   - `DATABASE_URL` = สตริงพอร์ต 6543 ต่อท้าย `?pgbouncer=true&connection_limit=5` แอปใช้ตัวนี้
   - `DIRECT_URL` = สตริงเดียวกันแต่พอร์ต 5432 ใช้ตอน `prisma migrate`
   ถ้ารหัสผ่านมีอักขระพิเศษ เช่น @ # / ต้องเข้ารหัส URL ก่อน (สคริปต์ติดตั้งทำให้)
4. `npx prisma migrate deploy` สร้างตารางและเปิด Row Level Security ทุกตาราง จึงไม่มีใครอ่านข้อมูลผ่าน REST API ด้วยคีย์ publishable ได้ แอปต่อฐานด้วยรหัสเจ้าของตารางโดยตรงจึงไม่โดน RLS
5. `.env` มีรหัสผ่านจริง ห้าม commit หรือส่งให้ใคร ถ้าหลุดให้เปลี่ยนรหัสใน Supabase > Project Settings > Database แล้วแก้ `.env`

ย้ายข้อมูลจากไฟล์ SQLite เดิม (`data/mybot.db`) ครั้งเดียว ต้องใช้ Node 22.5 ขึ้นไป

```powershell
npm run db:migrate-from-sqlite -- --replace   # คัดลอกทุกตาราง id เดิม แล้วนับเทียบ
npm run db:migrate-from-sqlite -- --verify    # ตรวจซ้ำอย่างเดียว
```

ไฟล์ `data/mybot.db` เก็บไว้เป็นสำรองเก่า แอปไม่ได้ใช้แล้ว

## 3. เลือก AI

ใช้พร้อมกันได้ ระบบลองตามลำดับแล้วข้ามตัวที่ล่ม

| ทางเลือก | ค่าใช้จ่าย | เหมาะกับ |
| --- | --- | --- |
| Ollama `qwen2.5:7b` | ฟรีบนเครื่อง | จัดหมวดภาษาไทย |
| Ollama `bge-m3` | ฟรีบนเครื่อง | ค้นตามความหมาย |
| Groq แพลนฟรี | ฟรี มีโควตา | เครื่องที่ไม่ลงโมเดล |
| Gemini แพลนฟรี | ฟรี มีโควตา | สำรองเมื่อ Groq เต็ม |

คีย์ Groq สร้างที่ https://console.groq.com  
คีย์ Gemini สร้างที่ https://aistudio.google.com/apikey

ถ้าบัญชี Groq ไม่มีโมเดลที่ตั้งไว้ แอปจะเลือกจากรายการที่คีย์นั้นใช้ได้เอง เช่น `openai/gpt-oss-120b`

การ์ดจอ RTX 3060 หรือแรมรวม 32 GB ใช้โมเดล 7B ได้ ถ้าเครื่องร้อนหรือ VRAM ไม่พอ ให้ตอบ `2` ตอนสคริปต์ถาม เพื่อใช้ `qwen2.5:3b`

พอร์ต 11434 บน Windows บางเครื่องอยู่ในช่วงที่ระบบกันไว้ ตรวจด้วย

```powershell
netsh int ipv4 show excludedportrange protocol=tcp
```

สคริปต์จะเลี่ยงช่วงนั้น แล้วใช้ 41434 แทน พร้อมตั้ง `OLLAMA_HOST=127.0.0.1:41434`

## 5. ติดตั้งส่วนขยาย Chrome

1. เปิด `chrome://extensions`
2. เปิดโหมดนักพัฒนา
3. กดโหลดส่วนขยายที่ไม่ได้แพ็ก
4. เลือกโฟลเดอร์ `extension` ในโปรเจกต์
5. เปิดป๊อปอัป MY-BOT ใส่ `http://localhost:8001` และโทเคนจากตอนท้ายของสคริปต์ติดตั้ง หรือจากหน้าตั้งค่า
6. ติ๊กเปิดดึงอัตโนมัติ

ส่วนขยายอ่านอย่างเดียว ไม่โพสต์และไม่คอมเมนต์

## 7. อ่านฟีดและสอนระบบ

หน้า **ฟีดลีด** กรองหมวด จังหวัด คะแนน และคำค้นได้ คะแนน 80 ขึ้นไปเป็นลีดร้อน

กดบันทึก ไม่สนใจ หรือเลื่อนสถานะเป็นทักแล้วและปิดการขาย หน้า **เรียนรู้** จะเสนอคำเฝ้าดูหรือคำต้องห้ามจากโพสต์เหล่านั้น

หน้า **สรุปรายวัน** ส่งตอนเช้าตามเวลาในหน้าตั้งค่า ค่าเริ่มต้น 08:00 เวลาไทย ถ้านาทีนั้น worker กำลังยุ่ง ระบบจะส่งทีหลังในวันเดียวกันเมื่อถึงรอบถัดไป โดยจำวันที่ส่งล่าสุดไว้ ไม่ส่งซ้ำในวันเดียวกัน

ฟีดซ่อนโพสต์ที่ข้อความตรงกันหรือความหมายใกล้กันเกิน 0.95 ในกลุ่มเดียวกันภายใน 7 วัน ติ๊ก **ยุบโพสต์คล้ายกัน** ออกได้ถ้าอยากเห็นตัวซ้ำ

ช่องค้นหาจัดอันดับด้วยคำที่ตรง (เช่น iPad) ร่วมกับความหมายเมื่อเปิด **ค้นตามความหมาย** แล้วตัดรายการข้อความซ้ำออก

## 8. Discord

ในดิสคอร์ดสร้าง webhook ของช่องที่ต้องการ แล้วใส่ URL ใน `.env` ชื่อ `DISCORD_WEBHOOK_URL` หรือในหน้าตั้งค่า

ลีดร้อนและสรุปรายวันจะเป็น embed มีคะแนน หมวด จังหวัด ลิงก์โพสต์ และคำตอบแนะนำให้ก๊อป ปุ่มทดสอบอยู่ที่หน้าการแจ้งเตือน

## 9. เปิดอัตโนมัติ

ตอนติดตั้งตอบ `y` ได้เลย จะได้ไฟล์ `MY-BOT.vbs` ในโฟลเดอร์ Startup ของบัญชีคุณ มันเปิด Ollama แล้วเปิดแอปแบบซ่อน

ถ้าเป็นผู้ดูแลระบบ สคริปต์ `scripts\windows\install-service.ps1` จะลอง Task Scheduler ด้วย และยังเขียนไฟล์ Startup สำรอง

เอาออก

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\uninstall-service.ps1
```

## 10. สำรองและกู้คืน

หลัง 03:00 ตามเวลาไทย ถ้าวันนั้นยังไม่เคยสำรอง แอปส่งออกทุกตารางจาก Supabase เป็น `data/backups/ปปปป-ดด-วว.json.gz` และเก็บ 14 วัน หน้าตั้งค่าแสดงไฟล์ล่าสุด ถ้าเครื่องปิดอยู่ตอนตีสาม มันจะสำรองในรอบแรกที่เปิดหลังเวลานั้น

กู้คืน (ข้อมูลในฐานจะถูกแทนที่ทั้งหมดด้วยไฟล์สำรอง)

1. หยุด MY-BOT
2. `npm run db:restore -- data/backups/ปปปป-ดด-วว.json.gz --replace`
3. เปิด MY-BOT อีกครั้ง

สำรองเองเมื่อไรก็ได้ด้วย `npm run db:backup` ได้ไฟล์ `data/backups/manual-....json.gz` นอกจากนี้ Supabase ยังมีสำรองของตัวเองในหน้า Database > Backups

## 11. อัปเดต

```powershell
git pull
npm install
npm run db:migrate
npm run build
```

แล้วเปิดแอปใหม่ ถ้ามีโพสต์เก่าที่ยังค้นตามความหมายไม่ได้ ให้รัน `npm run db:backfill-embeddings`

โพสต์ที่ยังถูกจัดด้วยกฎ จะถูกเข้าคิวใหม่เมื่อ worker เริ่ม และจัดหมวดอีกครั้งเมื่อมี Ollama, Groq หรือ Gemini

```powershell
npm run db:backfill-ai
npm run db:clean-samples
```

`db:clean-samples` ลบโพสต์ของแหล่งตัวอย่างที่ปิดอยู่ (ลิงก์ mybot-demo หรือชื่อมีคำว่าตัวอย่าง) ไม่ลบแหล่งเอง

หมวดอาหาร บริการ และเดินทางถูกเพิ่มใน migration รัน `npm run db:seed` อีกครั้งเพื่ออัปเดตคำจับคู่ของหมวดเดิม รวมถึง iPad มือถือ และแท็บเล็ตให้อยู่ในอุปกรณ์ไอที

## 12. ตรวจสุขภาพ

```powershell
npm run doctor
```

แต่ละบรรทัดขึ้นต้นด้วย PASS, WARN หรือ FAIL และมีคำใบ้เป็นภาษาไทย ไม่พิมพ์ค่าคีย์ลับ หน้า **วิธีใช้** ในแอปกดตรวจระบบได้เช่นกัน

## 13. คิว AI และประสิทธิภาพ

- แดชบอร์ดแสดง pending/running/done/failed/skipped เป็นภาษาไทย พร้อมเหตุผล retry และเวลาลองครั้งถัดไป งานผิดซ้ำ 10 ครั้งจะพัก กดปุ่มลอง AI ใหม่หรือรัน `npm run db:backfill-ai` เพื่อรีเซ็ตเฉพาะโพสต์ที่ยังไม่มีผล AI งานที่กำลังทำจะไม่ถูกรีเซ็ต
- เปิด worker ใหม่จะรักษา backoff และงานที่พักไว้ เมื่อเลือกใช้กฎ งานจะเป็น skipped โดยไม่ retry; เปลี่ยนกลับเป็น AI แล้ว worker จะรับต่อ
- AI consumer ตรวจงานใหม่ทุก 2 วินาทีและทำชุดถัดไปต่อเนื่อง รอบ fetch/backup แยกจาก consumer แต่ AI และ embedding ยังใช้โมเดลใน consumer เดียวเพื่อไม่แย่ง GPU
- รับโพสต์ไม่รอ embedding หรือการส่งแจ้งเตือนภายนอก เวกเตอร์เดิมใช้ซ้ำเมื่อข้อความและการตั้งค่าโมเดลตรงกัน เปลี่ยนโมเดลแล้ว worker สร้างให้ใหม่ เวกเตอร์ที่ยังอัปเดตไม่สำเร็จถูกเก็บไว้แต่ไม่ใช้ข้ามโมเดล
- ปุ่มสร้างเวกเตอร์ใหม่ในตั้งค่าเข้าคิวให้ worker ส่วน `npm run db:backfill-embeddings` เป็นงาน worker แบบสั่งรันด้วยมือ
- ค้นด้วยคำแบ่งหน้าจากทั้งฐานข้อมูลตามตัวกรองและเรียงคะแนน/วันที่ ค้นตามความหมายใช้ผู้สมัครล่าสุดประเภทละไม่เกิน 1,000 รายการ หน้า feed แจ้งขอบเขตและกลับมาค้นด้วยคำหากไม่มีโมเดลหรือเวกเตอร์ที่เข้ากันได้
- p50/p95 ของงาน AI แยกเวลาประมวลผลกับเวลาตั้งแต่เข้าคิวถึงเริ่มครั้งล่าสุด (รวม backoff) ใช้ตัวอย่างจาก 200 งานที่อัปเดตล่าสุด ส่วนเวลารับโพสต์/ค้นหาเก็บ 200 คำขอล่าสุดในหน่วยความจำของแต่ละโปรเซส รีเซ็ตเมื่อเปิดแอปใหม่

ตรวจสถิติรวมโดยไม่เปิดเผยเนื้อหาโพสต์หรือ secrets ด้วย `node scripts/audit-performance-local.mjs` รายงาน API แบบล็อกอินอยู่ที่ `GET /api/ai-queue`; public health ยังคงมีแค่ ok/version

ประเมินกฎภาษาไทยด้วย `npm run evaluate:classifier` ใช้ชุดแต่งขึ้น 20 ตัวอย่างเพื่อทดสอบเบื้องต้น ไม่ใช่ความแม่นยำบนข้อมูลจริง สร้างไฟล์ป้ายคำตอบที่เจ้าของตรวจแล้วตามรูปแบบ `tests/fixtures/classifier.th.json` และรัน `npm run evaluate:classifier -- --file=path/to/reviewed.json` เพิ่ม `--ai` เพื่อวัด provider chain ตามตั้งค่าปัจจุบัน (ส่งข้อความไป provider ที่ตั้งไว้) คำสั่งนี้ไม่เขียนโพสต์หรือส่งแจ้งเตือน ควรเก็บชุดข้อมูลจริงไว้นอก git และวัด precision/recall ของ buyer ก่อนปรับโมเดล

ก่อนอัปเดตให้หยุดเฉพาะ MY-BOT แล้วรัน migrate/build ตามขั้นตอนเดิม การ build บน Windows ขณะ web/worker ใช้ Prisma DLL อาจเกิด EPERM; อย่ารัน integration tests ที่ใช้ Prisma พร้อมกับขั้น generate ของ build

### การอัปเดตความปลอดภัยและเสถียรภาพ

ดู [รายละเอียด Migration, Backup v2, Restore แบบ Transaction และผลทดสอบ](SECURITY-STABILITY.th.md) ก่อนอัปเดต Local/Render ที่ใช้ฐานร่วมกัน ต้องหยุด Worker ทุก Host ก่อน Migrate และไม่รัน Worker ต่างรุ่นพร้อมกัน

ตรวจไฟล์สำรองโดยไม่ต่อฐานได้ด้วย `npm run db:restore -- <file> --check` ไฟล์ v1 เดิมต้องเพิ่ม `--allow-legacy` เพราะข้อมูลบางตารางไม่มีใน Backup รุ่นนั้น ห้ามทดสอบ Restore บนฐานจริง

DB Integration Tests ใช้เฉพาะ `TEST_DATABASE_URL` ที่ตั้งอย่างชัดเจน ไม่ใช้ `DIRECT_URL` เป็นทางเลือกอัตโนมัติ หากไม่มีฐานทดสอบจะ Skip ชุดที่ต้องใช้ฐาน Node สำหรับชุดทดสอบตาม Lockfile ต้องเป็น 22.22.2+, 24.15.0+ หรือ 26+

## แก้ปัญหาที่พบบ่อย

- **พอร์ต 11434 ถูกกันไว้:** ใช้ `OLLAMA_HOST=127.0.0.1:41434` แล้วเปิด `ollama serve` ใหม่ ใส่ `OLLAMA_BASE_URL=http://127.0.0.1:41434` ใน `.env`
- **PowerShell ห้ามรันสคริปต์:** ใช้ `-ExecutionPolicy Bypass -File` ตามคำสั่งด้านบน ไม่ต้องเปลี่ยนนโยบายทั้งเครื่อง
- **ต่อฐานข้อมูลไม่ได้ (P1001 หรือ password authentication failed):** เช็กเน็ต และ `DATABASE_URL`/`DIRECT_URL` ใน `.env` ว่ารหัสผ่านถูกและโปรเจกต์ Supabase ไม่ได้ถูกพัก (โปรเจกต์ฟรีจะพักถ้าไม่ใช้ 7 วัน กด Restore ในหน้า Supabase)
- **migrate ค้างหรือขึ้น prepared statement:** ตรวจว่า `DATABASE_URL` มี `pgbouncer=true` และ `DIRECT_URL` ใช้พอร์ต 5432
- **npm run doctor แดงที่ฐานข้อมูล:** รัน `npm run db:migrate`
- **embedding ไม่ผ่าน:** `ollama pull bge-m3` แล้วกดทดสอบ embedding ในหน้าตั้งค่า
- **Ollama สลับโมเดลจนช้า:** ตั้ง `OLLAMA_MAX_LOADED_MODELS=2` กับ `OLLAMA_KEEP_ALIVE=30m` ที่โปรเซส `ollama serve` แล้วเปิด Ollama ใหม่ สคริปต์ติดตั้งและไฟล์ Startup ทำให้แล้ว แอปยังส่ง keep_alive 30 นาทีทุกครั้งที่คุยหรือฝังข้อความ และอุ่นโมเดลแชทกับ embedding ตอน worker เริ่ม
- **จัดหมวดแล้วโปรเซสล่ม หรือค้างสถานะ running:** OCR รันเฉพาะ worker ถ้าอ่านรูปไม่สำเร็จ งานถูกปักว่าไม่สำเร็จแล้วจัดหมวดต่อโดยไม่มีข้อความจากรูป งานที่ค้างเกิน 2 นาทีถูกคืนเข้าคิว รายละเอียดอยู่ที่ `data/mybot.log` ส่วนข้อความบนจอของตัวเปิดอัตโนมัติไปที่ `data/mybot-console.log`
- **ดึงแหล่งแล้วขึ้นข้อผิดพลาด:** เปิดหน้าแหล่งข้อมูล จะมีบรรทัดสีแดงขึ้นต้นว่าสาเหตุ พร้อมรหัส HTTP หรือข้อความจาก RSS
- **ตรวจว่าแอปยังมีชีวิต โดยไม่ต้องล็อกอิน:** เปิด `http://localhost:8001/api/v1/health` ได้ `{ "ok": true, "version": "..." }` ไม่มีคีย์หรือค่าลับ
- **ส่วนขยายส่งไม่เข้า:** โทเคนต้องตรงกับหน้าตั้งค่า และที่อยู่ต้องเป็นพอร์ต 8001
- **ลืมรหัสผ่าน:** หยุดแอป เปิด Supabase > Table Editor ลบแถวในตาราง `Session` และ `Owner` แล้วเปิด `http://localhost:8001` จะเข้าหน้าตั้งรหัสใหม่ ข้อมูลลีดยังอยู่
