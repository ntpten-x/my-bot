## ประสิทธิภาพตัวอ่าน

heartbeat แสดง Extension 1.11.1 ออนไลน์และมีโพสต์รับเข้า ข้อมูล reader metrics ณ รอบแรก: 17 รอบ, พบใหม่ 63, จบตรวจ 4, นัดอ่านต่อ 13, เฉลี่ย 34 วินาทีต่อรอบ อัตรา 6.5 โพสต์ต่อนาทีเป็นเวลาที่กำลังอ่าน ไม่ใช่อัตราต่อเวลาจริงทั้งวัน

ยังไม่ควรสรุปว่าอ่านครบหรือเสถียรตลอดวัน: error log ของ Extension มีเหตุอ่านแท็บหมดเวลา 27 ครั้งใน 24 ชั่วโมง และยังมี outbox รอส่งอยู่ สถิติ reader metrics กับ error log มีขอบเขตต่างกัน ต้องดูร่วมกัน การตรวจรอบนี้ไม่ได้แก้ timeout ทั้งระบบหรือรับรองความครบของโพสต์

## แก้ใน workspace แล้ว

1. เพิ่มแผงตรวจเส้นทางส่งในหน้า Auto Comment ระบุ Dry Run, Worker, อุปกรณ์/บัญชีที่ผูกกับแต่ละกฎ, สวิตช์รับงาน, journal ค้าง และกฎที่ถูกพัก แยก AI ออกจากเงื่อนไขความพร้อมของกฎที่ไม่ใช้ AI
2. รีเฟรช readiness พร้อม dashboard แทนอ่านครั้งเดียวตอนเปิดหน้า หากตรวจอุปกรณ์ไม่สำเร็จแสดงว่าตรวจไม่ได้ ไม่ใช้สถานะเก่ามายืนยันความพร้อม
3. `extension/parser.js`: แปลงลิงก์ single-post `multi_permalinks=<เลขเดียว>` เป็น permalink ของโพสต์ ป้องกันการ dedupe ด้วย path กลุ่มเดียวกันจนคนละโพสต์หาย และให้ direct permalink มาก่อน fallback ไม่รองรับ collection หลายรหัสหรือโฮสต์ปลอม
4. ไม่เปลี่ยนลิงก์ที่มี comment_id/reply_comment_id ให้เป็นเป้าหมายส่ง ถ้าพบลิงก์โพสต์หลักที่ชัดเจนใน article จึงเลือกใช้ลิงก์นั้น `browserTarget` ยังปฏิเสธ comment/reply links ตามเดิม
5. แก้การเทียบชื่อกลุ่ม vanity URL ระหว่าง source ที่เก็บตัวพิมพ์เดิมกับ post URL ที่ ingest แปลงเป็นตัวพิมพ์เล็ก ทั้งเซิร์ฟเวอร์และ DOM sender ใช้ชื่อกลุ่มรูปแบบเดียวกัน แต่ยังไม่ยอมรับกลุ่มอื่น และไม่เดาความสัมพันธ์ alias กับ numeric ID
6. เพิ่ม Extension/expected version เป็น 1.11.2 ต้อง deploy เว็บและติดตั้ง Extension รุ่นเดียวกัน การแก้นี้ยังไม่ขึ้น production จนกว่าจะ push/deploy และ reload ส่วนขยาย

## การทดสอบและขั้นตอนทดสอบจริง

เพิ่ม regression สำหรับ multi_permalinks สองโพสต์, comment-only links, โฮสต์ปลอม, collection, vanity URL ต่างตัวพิมพ์ และสถานะอุปกรณ์ที่ผูกกับกฎโดยตรง ตรวจ Chrome ด้วย API จำลอง: แสดง Dry Run/สวิตช์ปิด, เพิ่ม/ลบข้อความ, บันทึกกฎไม่รอ AI ผ่าน มือถือ 390px ไม่ล้น ไม่มี page error

ชุดทดสอบ DOM และ Worker เป็นข้อมูลสังเคราะห์ การทดสอบ DB ที่ต้องใช้ TEST_DATABASE_URL ข้ามเมื่อไม่มีฐานแยก ไม่ใช้ production เป็นฐานทดสอบ

ผลตรวจโค้ดสุดท้าย: `npm.cmd test` ผ่าน 509 รายการ ข้าม 88 รายการ (60 ไฟล์ผ่าน, 7 ไฟล์ข้าม); `npm.cmd run build` ผ่าน; `git diff --check` และ `node --check` สำหรับ parser/browser-comment ผ่าน ไม่มี migration ใหม่

การส่ง Facebook จริงยังไม่ผ่านการพิสูจน์ในรอบนี้ รอลิงก์โพสต์และข้อความทดสอบจากเจ้าของตามคำถามที่ส่งไว้ และต้องเปิดรับงานบน Extension ก่อน ไม่ปิด Dry Run ทั้งระบบเพื่อค้นหาโพสต์ใดก็ได้มาทดลองเอง

เมื่อได้เป้าหมายแล้ว ให้ตรวจว่าเป็นโพสต์กลุ่มใน allowlist ข้อความครบ ไม่ซ้ำ ไม่ใช่โพสต์ก่อนเริ่มรอบ และบัญชีถูกต้อง จำกัดการทดสอบหนึ่งคอมเมนต์ เก็บเพดานเดิม ตรวจ DOM แบบไม่กดก่อน แล้วจึงใช้เส้นทางส่งจริงของ Extension ตรวจผลจากลิงก์คอมเมนต์และบัญชีผู้เขียน หากคลุมเครือให้พักและตรวจเอง ไม่ retry

ไม่ต้อง migration หรือเปลี่ยนข้อมูลลับ การย้อนกลับใช้ application/Extension รุ่นคู่เดิม โดยคงประวัติงานและ dedupe keys ทั้งหมดไว้
