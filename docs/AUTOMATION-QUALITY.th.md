# ตรวจคุณภาพฟีดและคอมเมนต์

เปิด **แหล่งข้อมูล → ตรวจคุณภาพฟีดและข้อเสนอตารางอ่าน** หรือ **คอมเมนต์อัตโนมัติ → ตรวจคุณภาพฟีด ความหน่วง และแหล่งข้อมูล** (`/automation-quality`) หลังเข้าสู่ระบบ หน้านี้อ่านข้อมูลตามสั่ง ไม่มี polling ไม่สั่งอ่านกลุ่ม ไม่ claim/authorize/send และไม่เปลี่ยนโควตา ช่วงเวลา quiet หรือรอบอ่านเอง

## 1. ตรวจตัวอย่างที่เห็นจริง

เลือกแหล่งข้อมูล วาง URL ที่เจ้าของเห็นด้วยตนเอง 1–50 รายการ (สูงสุด 32 KiB) หนึ่งรายการต่อบรรทัด รูปแบบ:

```text
URL | buyer/seller/ad/unknown | true/false
```

สองช่องท้ายเว้นว่างได้: ช่องว่างคือยังไม่ติดป้าย; `unknown` คือคำตอบที่คนตรวจแล้วว่าไม่ทราบเจตนา `true` ระบุว่าตัวอย่างนี้ต้องการข้อความเต็ม URL ถูก parse เท่านั้น ไม่มีการ fetch Facebook/URL ของผู้ใช้ API ค้นเฉพาะ source ที่เลือกด้วย post keys เดิม ตรวจ alias ซ้ำอีกครั้ง จำกัด candidate 500 แถว ถ้าเกินจะบอก unknown แทนสรุปว่าหาย

- สัดส่วนพบในฐานเป็นเพียง coverage ของตัวอย่างที่คนเลือก ไม่ใช่ recall ทั้งกลุ่ม
- precision/recall แยก intent คำนวณเฉพาะรายการที่พบและคนติดป้าย แสดงจำนวนที่หาย ไม่มีป้าย และป้ายขัดแย้งแยก ห้ามนำไปอ้างความแม่นยำของทั้งระบบโดยไม่รายงานวิธีเลือกตัวอย่าง
- URL alias ซ้ำไม่นับเพิ่ม ป้ายขัดแย้งตัดออกจากตัวหารการจัดประเภท
- `truncated=true` บอกได้ว่าระบบยังมีข้อความไม่ครบ แต่ `false` ไม่พิสูจน์ว่าอ่านครบทั้งหมด เวลาดึงที่ไม่มีในข้อมูลแสดงไม่ทราบ ไม่ใช้ createdAt แทน
- ดาวน์โหลด JSON เก็บผลเปรียบเทียบซ้ำภายหลังได้ ไม่มีข้อความโพสต์ คีย์ หรือ token ไม่แก้ป้ายในฐานหรือสร้างงานส่ง

## 2. ตรวจงานคอมเมนต์และหลักฐาน

ในหน้าคอมเมนต์ กด **ตรวจเส้นทางและหลักฐาน** ของงานนั้น หรือวาง Job ID ในหน้าคุณภาพ API อ่าน log ล่าสุดได้ 100 แถว พร้อมแจ้งว่าตัดรายการ และค้น milestone แรกแยกเพื่อไม่ให้ประวัติที่ยาวซ่อนเวลา ready/observed

Timeline ลำดับส่งใช้ ingest → สร้างงาน → ready → dispatch → observed แยกเวลาสะสมจาก ingest กับช่วงรอระหว่างขั้น เวลา endpoint ขาด อยู่อนาคต หรือเรียงย้อนกลับแสดงไม่ทราบ งาน AI และ evaluation ล่าสุดเป็น snapshot แยก เพราะอาจเกิดหลังสร้าง/ส่งงานแล้ว ไม่ใช่ milestone ถาวรของรอบส่งนี้ การประมวลผลที่ไม่มี timestamp เสร็จแสดงไม่ทราบ

หลังอัปเดต backend รายงาน `observed` จาก Extension จะเก็บ Comment ID ตัวเลขลงช่อง receipt เดิม เมื่อ URL ผ่าน HTTPS, host Facebook, group/post target และค่าทั้งหมดของ Comment ID แล้วเท่านั้น ไม่เก็บ tracking หรือ fragment ดิบ การรายงานซ้ำไม่เขียนทับผล terminal งานเก่าไม่มี receipt จะระบุไม่ทราบ ไม่แต่งลิงก์ย้อนหลัง ผล browser_observed คือพบใน UI ไม่ใช่การยืนยันจาก Meta API

งาน uncertain ยังคงไม่ส่งซ้ำเอง เปิดโพสต์ ตรวจบัญชีและข้อความใน Facebook ด้วยตนเอง อย่าตีความว่าไม่เห็นคอมเมนต์ในหน้าจอครั้งเดียวแปลว่าไม่ได้ส่ง หน้าตรวจไม่มีปุ่ม retry หรือเปลี่ยนผล ไม่เรียก reconcile ใน Chrome เอง การอนุมัติส่งจริงและการกด Stop ยังคงกติกาเดิม

## 3. คุณภาพเงื่อนไขก่อนส่ง

ต่อยอด gate เดิมที่ปฏิเสธข้อความตัดทอน โฆษณา งานประมวลผลไม่เสร็จ โพสต์เก่า กลุ่ม/บัญชีไม่ตรง และข้อความปิดการหา เพิ่มรูปแบบถอนคำขอ “เลิกตามหา”, “ยกเลิกการหา”, “ปิดการตามหา” โดยไม่ตัดคำขอที่บอกว่ายังไม่ยกเลิก เจ้าของติดป้าย buyer ไว้ก็ไม่ข้าม gate ถอนคำขอ ผลทดสอบข้อความแต่งขึ้นเป็น regression ไม่ใช่ค่าความแม่นยำจริง ต้องใช้ตัวอย่างที่เจ้าของตรวจเพิ่ม

## 4. ข้อเสนอตารางอ่าน

สรุปโพสต์ไม่ซ้ำที่นำเข้าใน 7/30 วัน สูงสุด 100 แหล่งแรก บอกส่วนที่ไม่รวม ผลตอบ/ติดต่อ/ชนะเป็นสถานะปัจจุบันของโพสต์ในกลุ่มเวลานี้ ไม่ใช่รายได้ที่เกิดในช่วงหรือการพิสูจน์ว่าระบบเป็นเหตุให้ขายได้ จำนวน buyer เป็น label ที่ระบบเก็บ ไม่ใช่ buyer ที่คนยืนยันทั้งหมด

เสนอปรับเมื่อมีหลักฐานอ่านล่าสุดของรุ่นปัจจุบันและ heartbeat สด มีอย่างน้อย 20 โพสต์/3 รอบอ่าน พิจารณาซ่อม error, ข้อความไม่ครบ และคิวค้างก่อน ไม่เพิ่มความถี่จากคะแนนเพียงอย่างเดียว การลดความถี่ต้องมีอย่างน้อย 50 โพสต์ เจ้าของข้าม 20 และยังไม่มีผลติดต่อ ข้อเสนอเป็น heuristic ที่ต้องทดลอง ไม่ใช่การปรับค่าอัตโนมัติ เจ้าของตรวจแล้วตั้งค่าที่หน้าแหล่งข้อมูลเดิม ค่าเริ่มต้น 3/10/30, quiet และ quota ไม่เปลี่ยน

## 5. เวลาประมวลผลและความต่อเนื่อง

ตาราง p50/p95 บนเว็บเป็นไม่เกิน 200 ตัวอย่างต่อ metric ใน web process ปัจจุบัน รีเซ็ตเมื่อเริ่มใหม่ ไม่ใช่ข้อมูลทุกเครื่อง ห้ามบวกหรือลบ percentile คนละช่วงแทนเวลา end-to-end เวลา capture อาศัยนาฬิกา browser ไม่ใช่เวลาตั้งแต่โพสต์เผยแพร่

อ่านวิธีเก็บ 24/72 ชั่วโมง ตรวจ gaps/backlog/uncertain/version และรัน recovery verifier แบบ offline ใน [AUTOMATION-SOAK.th.md](AUTOMATION-SOAK.th.md) เครื่องมือเก็บสถิติไม่เปิด collection หรือส่งแทนเจ้าของ CPU/RSS ที่วัดเป็นของ observer เอง ไม่ใช่ Chrome/ทั้งเครื่อง schema เดิมไม่มี version ผูกกับ comment job/log จึงไม่อ้างว่างานย้อนหลังเป็นผลรุ่นปัจจุบัน

## การนำไปใช้

ไม่มี migration, permission ใหม่ หรือการเปลี่ยน protocol Extension ในรอบนี้ ต้อง build/restart เฉพาะ web ที่รับอัปเดตจึงเห็นหน้า/API ใหม่ หากมี worker แยกให้ใช้ build เดียวกันเพื่อให้กฎถอนคำขอและ receipt ตรงกัน ไม่รีสตาร์ต Chrome/desktop หรือเริ่มระบบส่งแทนเจ้าของ

Test/build และข้อมูลจำลองไม่รับรองการอ่านครบหรือส่งสำเร็จบน Facebook จริง ต้องเก็บหลักฐานตามรุ่นที่ติดตั้งและผ่านเวลาทดลองจริง ส่วนการส่งทดสอบต้องได้รับอนุมัติแยกตาม AGENTS.md
