# แยกเครื่องทำงานของบอทเพื่อความเสถียร

## รูปแบบที่แนะนำ

ให้ Chrome + ส่วนขยายทำงานบน **เครื่องเฉพาะบอทที่เปิดเดสก์ท็อปและหน้าต่าง Chrome ค้างไว้** เจ้าของเปิดเว็บ MY-BOT จากเครื่องใช้งานของตนเอง การเปิด/สลับหน้าต่างของตัวส่งคอมเมนต์จะเกิดบนเครื่องบอท โดยไม่แตะหน้าจอเครื่องเจ้าของ

VM แบบมีเดสก์ท็อปเป็นอีกทางเลือก เมื่อเครื่องมีทรัพยากรเพียงพอและ guest ยังรัน/แสดงผลต่อเนื่องหลังย่อหน้าต่าง console ต้องทดสอบ hypervisor/remote desktop ที่ใช้จริงก่อนถือว่าพร้อม ห้ามสรุปว่าเพียงย่อ VM หรือย่อ RDP แล้วเบราว์เซอร์จะโหลดได้เท่าเดิมทุกระบบ ส่วนโปรไฟล์ Chrome แยกบนเครื่องเดิมช่วยแยกข้อมูล แต่ไม่แยกหน้าจอและไม่แก้ throttling จากการย่อ

เลือกให้เว็บ/worker มีโฮสต์หลักตามการติดตั้งเดิม ไม่เปิด worker เพิ่มโดยไม่ตรวจโฮสต์ที่รันอยู่ หากย้ายโฮสต์ ให้หยุดเว็บ/worker เดิมก่อนเริ่มตัวใหม่ ไม่ต้องย้ายฐานข้อมูล Supabase และไม่ต้องคัดลอก cookies/รหัสผ่าน/โทเคนอุปกรณ์จาก Chrome ส่วนตัว

## เตรียม Chrome ของบอท

สั่งจากโฟลเดอร์โครงการบนเครื่องบอท (Node.js 20 ขึ้นไป และ Chrome ติดตั้งแล้ว):

```sh
npm run browser:bot -- --check
npm run browser:bot
```

ค่าเริ่มต้นเปิด MY-BOT ที่ `http://localhost:8001` พร้อม Facebook ใน **โปรไฟล์ใหม่เฉพาะบอท** อยู่ที่ `data/browser-profile/` เรียกคำสั่งเดิมซ้ำเพื่อใช้โปรไฟล์เดิม หาก Chrome อยู่นอกตำแหน่งมาตรฐาน ให้ใช้ `--chrome` ตามด้วย path executable โดยใส่เครื่องหมายคำพูดเมื่อ path มีช่องว่าง

ถ้าเว็บรันอยู่อีกเครื่อง ใช้ URL HTTPS ของเว็บที่อัปเดตให้รองรับส่วนขยายเวอร์ชันปัจจุบันแล้ว เช่น:

```sh
npm run browser:bot -- --url https://your-mybot.example
```

ไม่ใช้ HTTP ผ่าน IP ของเครื่องอื่น และไม่ส่งรหัสผ่านหรือ token ใน URL localhost หมายถึงเครื่องที่ Chrome รัน หากเว็บยังอยู่บนเครื่องเจ้าของ localhost บนเครื่องบอทจะเข้าเว็บนั้นไม่ได้ ต้องจัดให้มี URL HTTPS ที่เข้าถึงได้ก่อน คู่มือ Render อยู่ใน `docs/RENDER.th.md` การเตรียมนี้ยังไม่ deploy เว็บ ไม่สร้าง VM และไม่เริ่มแสดงความคิดเห็นจริง

ครั้งแรก:

1. ล็อกอิน Facebook ด้วยตนเองใน Chrome โปรไฟล์บอท และจัดการ checkpoint หาก Facebook ขอ
2. `chrome://extensions` → Developer mode → Load unpacked → เลือก `extension/` ในเครื่องบอท คำสั่ง launcher ไม่ติดตั้ง extension ให้อัตโนมัติ
3. เข้า MY-BOT ด้วยบัญชีเจ้าของ สร้าง pairing code ในตั้งค่า แล้วจับคู่ส่วนขยายใหม่ ห้ามคัดลอก device token เดิม โค้ดส่วนขยายและเว็บต้องมีเวอร์ชันที่ยอมรับตรงกัน
4. ตรวจ **ภาพรวมระบบ** ให้เห็นอุปกรณ์และบัญชี Facebook ของเครื่องบอทออนไลน์
5. ในบัญชี/ชุดคอมเมนต์ที่เกี่ยวข้อง เลือกอุปกรณ์บอทใหม่แทนอุปกรณ์เดิม ตรวจบัญชีและกลุ่มที่อนุญาตอีกครั้ง ระบบจะไม่โยกสิทธิ์ส่งอัตโนมัติ
6. พัก/ปิดส่วนขยายเครื่องเดิมเพื่อไม่ให้ดึงข้อมูลซ้อนโดยไม่จำเป็น อย่าลบอุปกรณ์เก่าที่ยังมีงานส่งคลุมเครือ ให้ตรวจประวัติก่อน

`--check` ตรวจพบ Chrome และเดสก์ท็อปได้เท่านั้น ไม่ยืนยันว่าเว็บ/ฐานข้อมูล/ส่วนขยาย/Facebook พร้อมใช้งาน `--help` ไม่เปิดเบราว์เซอร์ การรันคำสั่งเปิด Chrome ไม่เปิด automation หรือเปลี่ยนกฎที่ตั้งไว้

## รักษาความเสถียร

- ให้เครื่องบอทตื่นอยู่และ Chrome ไม่ถูกย่อ ไม่ล็อกหรือปิด session เดสก์ท็อประหว่างทำงานที่ต้องใช้ editor ต้องตั้งค่าพลังงานตามเครื่องจริงด้วยเจ้าของเอง launcher ไม่เปลี่ยนค่า OS
- ใน `chrome://settings/performance` เพิ่ม Facebook และเว็บ MY-BOT ใน **Always keep these sites active** เพื่อลดการ discard โดย Memory Saver รายการนี้ไม่ยกเลิก throttling ทุกชนิด ไม่ปิดระบบความปลอดภัย Chrome และไม่ใช้ flags ที่ปลอม visibility
- ใช้เพดานการอ่านปัจจุบัน: สูงสุดสองงานพร้อมกัน ลดเหลือหนึ่งเมื่อฟีดโหลดติดขัด/อ่านย้อนหลัง ตรวจล่าสุดสลับกับย้อนหลัง ไม่เพิ่มแท็บจำนวนมากเพื่อไล่ความเร็ว
- คง outbox/receipts, checkpoint และข้อห้าม retry ผลส่งคลุมเครือ ไม่กดเริ่มซ้ำเพื่อแก้บัญชีที่ Facebook จำกัด
- อัปเดต Chrome/ส่วนขยายและรีสตาร์ตตามแผนหลังหยุดงาน ไม่คัดลอก `data/browser-profile/` เข้า git หรือแบ็กอัปทั่วไป เพราะมีข้อมูลล็อกอินและ device token โปรไฟล์นี้ถูก gitignore แล้ว

## ตรวจรับก่อนใช้จริง

เริ่มจากการอ่านข้อมูลอย่างเดียว: เพิ่มโพสต์ล่าสุดระหว่างกลุ่มมีงานย้อนหลัง ตรวจว่าได้รับโพสต์ใหม่และจุดย้อนหลังยังคืบหน้า ปล่อยอ่านต่ออย่างน้อย 30 นาที พร้อมสังเกต heartbeat, outbox และข้อผิดพลาด จากเครื่องเจ้าของให้ย่อ Chrome ของตัวเอง แล้วตรวจว่าเครื่องบอทยังทำงานและไม่มีหน้าต่างเด้งบนเครื่องเจ้าของ

ถ้าใช้ VM/remote desktop ให้ย่อ/ตัดการเชื่อมต่อ viewer แล้วตรวจ heartbeat **พร้อมจำนวนโพสต์ที่รับจริง** ไม่ใช้ heartbeat อย่างเดียวเป็นหลักฐานว่า Facebook ยังโหลดได้ หากไม่คืบหน้า ให้แก้การแสดงผล guest หรือใช้เครื่องเฉพาะจริง

ทดสอบคอมเมนต์จริงได้หลังเจ้าของอนุมัติการส่งแยกต่างหากเท่านั้น การตั้งค่าเครื่อง/จับคู่อุปกรณ์ไม่ถือเป็นอนุมัติการส่ง ผลรอบเตรียมนี้ยังไม่ยืนยันประสิทธิภาพ Chrome บนเครื่องบอทจริง

อ้างอิง: [Chrome profiles](https://support.google.com/chrome/answer/2364824), [Memory/Energy Saver และผลต่อเว็บ](https://developer.chrome.com/blog/memory-and-energy-saver-mode), [Chrome background throttling](https://blog.chromium.org/2020/11/tab-throttling-and-more-performance.html)

## ผลตรวจเครื่องมือในโครงการ

ชุดทดสอบผ่าน 709 tests / 79 files และ `npm run build` ผ่าน ทดสอบการแยก path โปรไฟล์ การปฏิเสธ URL ที่มีข้อมูลล็อกอิน/HTTP เครื่องอื่น การตรวจเดสก์ท็อป Linux และการค้นหา Chrome บน Windows โดยไม่เปิด Chrome จริง เครื่องมือ `--check` บนสภาพแวดล้อมพัฒนานี้แจ้งว่าไม่พบ Chrome จึงยังไม่ได้ทดสอบการเปิดเบราว์เซอร์ การจับคู่ หรือการอ่าน Facebook บนเครื่องเฉพาะจริง

## มีเครื่องเดียว

เครื่องเจ้าของมี WSL2 อยู่แล้ว ใช้จอเสมือนสำหรับเบราว์เซอร์บอทในเครื่องเดิมได้ ดู [คู่มือจอเสมือนบน WSL](SINGLE-PC-BOT.th.md) เริ่มด้วย `npm run browser:desktop` วิธีนี้ใช้เบราว์เซอร์แบบมีหน้าจอในจอเสมือน ไม่ต้องเปิด Hyper-V เพิ่ม และยังต้องทดสอบการโหลด Facebook จริงหลังเจ้าของล็อกอิน/จับคู่
