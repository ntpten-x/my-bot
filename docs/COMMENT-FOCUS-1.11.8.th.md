# การส่งคอมเมนต์ร่วมกับตัวอ่านฟีด — 1.11.8

แก้การแย่งโฟกัสในจอเฉพาะบอท: ตัวส่งรับ focus lease ก่อนเปิดหน้าโพสต์ และปล่อยเมื่อจบ/ล้มเหลว ตัวอ่านใช้ mutex เดียวกันก่อนเปลี่ยนแท็บหรือโฟกัสหน้าต่าง และพักการอ่านเมื่อพบ lease จึงไม่สลับไปหน้าต่างอ่านขณะ editor กำลังรับข้อความ

lease เก็บใน session พร้อมเวลาหมดอายุ 3 นาที หาก MV3 หยุดกลางงานจะไม่ยึดโฟกัสค้างตลอดไป การกู้คืน journal ยังคงรายงานผลเท่านั้น ไม่เรียกส่งซ้ำ ตัวเลือกอนุญาตรับคอมเมนต์ใน popup ยังเป็น opt-in แยกจากโหมดจอเฉพาะ และสิทธิ์ server ยังตรวจ rule/device/account/consent/revision/global control ก่อนออก grant

การ executeScript แต่ละครั้งของตัวส่งจำกัด 5 วินาที หากค้างก่อนเรียกส่งจะรายงานว่าไม่สำเร็จและปล่อยโฟกัส หากเรียก send ไปแล้วไม่ทราบผลจะเป็น uncertain และไม่ retry คลิก ขอบเขตนี้ไม่ใช่การยกเลิกทุกคำสั่งที่ Chrome รับไว้แล้ว ต้องรักษาเงื่อนไข permit/one-click ฝั่ง DOM เดิม

## ติดตั้ง

อัปเดตเว็บให้คาดหวัง **1.11.8** และ Reload ส่วนขยายรุ่นเดียวกันในจอเสมือน ไม่ต้องสร้าง device ใหม่หากใช้โฟลเดอร์ extension เดิม หากเปลี่ยนโฟลเดอร์แล้วได้ device ใหม่ ต้องเลือกอุปกรณ์ใหม่นั้นในชุดคอมเมนต์ ระบบจะไม่เดาเปลี่ยนอุปกรณ์แทนเมื่อพบหลายเครื่องออนไลน์

ตรวจสามจุดก่อน Start: บัญชี Facebook ตรง, popup อนุญาตรับงาน, ชุดคอมเมนต์ผูก device ที่ออนไลน์จริง การเปิด global control เพียงอย่างเดียวไม่ทำให้กฎที่ผูกอุปกรณ์เก่ารับงานได้

ระบบเลือกเฉพาะโพสต์ที่ผ่านกฎและอยู่หลังขอบเขต Start ปัจจุบัน การเปิดย้อนหลังบนหน้าฟีดไม่ได้แปลว่าทุกโพสต์ในหน้าจะถูกเมนต์ทันที ไม่แก้ timestamp หรือยกเลิก dedupe เพื่อบังคับสร้างงาน งาน uncertain เดิมต้องตรวจเองและไม่ใช้ทดสอบส่งซ้ำ

## หลักฐานทดสอบ

ทดสอบ worker จริงด้วย Chrome transport จำลอง: opt-in/account pause/authorization loss/expired grant/report outage, เรียก send ครั้งเดียว, กู้ pending report เดิม, ถือและปล่อย focus lease, ไม่ claim ขณะ lease เดิมยังไม่หมดอายุ, preparation timeout ไม่ขอ grant และ send timeout เป็น uncertain ตัวอ่าน VM ตรวจว่าไม่โฟกัสขณะ comment lease active และ yield โดยไม่อ่าน snapshot เพิ่ม

การทดสอบเหล่านี้ไม่ใช่หลักฐานว่ามีคอมเมนต์บน Facebook จริง ต้องมีผล browser_observed พร้อม comment permalink ที่ตรงกับโพสต์/บัญชี และตรวจหน้าจอจริงหลังทดสอบส่งที่เจ้าของเลือก ห้ามสรุปว่าส่งสำเร็จจาก claim/authorize หรือ click เพียงอย่างเดียว

ผลทดสอบรอบแก้ไข: `npm test` ผ่าน 728 tests / 83 files กับ Postgres ชั่วคราวที่กำหนด `TEST_DATABASE_URL` ชัดเจน และ `npm run build` ผ่าน ไม่ใช่การส่งจริง รุ่นโค้ดในโฟลเดอร์ส่วนขยายที่ติดตั้งเดิมอัปเดตแล้ว ต้อง Reload ที่ chrome://extensions เพื่อโหลด manifest/worker ใหม่
